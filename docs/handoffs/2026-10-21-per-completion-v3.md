# 후지모토 PER 빈값 보완 v3

승인된 [ExecPlan](../superpowers/plans/2026-10-21-per-completion-v3.md)에 따른 작업이다.
KRX 양수 PER은 유지하고, DART 공시의 음수 보통주 EPS를 전략상 비교 제외 근거로
구분한다. 이는 KRX가 빈값을 보낸 이유를 제공기관이 확인했다는 뜻이 아니다.
우선주·종류주권·스팩은 기준일의 공식 종목 구분으로만 비교 대상에서 제외한다.
자료 부족·공시 충돌·양수 EPS인데 PER 미제공인 경우는 계속 차단한다.

## 조사에서 확인한 사실

2026-10-21 KRX 원문 2,714종목 중 PER 1,167개가 `-`였고, 같은 종목의 EPS도 `-`였다.
원문에 존재하는 숫자 PER을 수집 과정에서 잃은 사례는 0개였다. 적자와 제공 범위,
자료 부족이 섞여 있으므로 빈값을 일괄 0 또는 업종 평균으로 대체하지 않는다.

KIS 모의환경 표본 12종목을 대조했으나 즉시 사용할 수 있는 양수 보완을 검증하지 못했다.
삼성제약 현재가 EPS -155는 KIS 재무비율 API의 202412 행과 같고, DART/KRX의
2025년 EPS +123과 기준연도가 다르다. IBKS제24호스팩의 +33도 KIS 202412 행과 같고
DART 2025년 기본 EPS는 +27이다. 에스엘·유진투자증권은 KIS EPS가 지배주주 순이익을
현재 상장주식수로 나눈 값과 반올림 수준에서 일치한다. 이 관측을 모든 종목의 공식 산식으로
일반화하지 않는다. KIS 실전용 별도 자격증명은 운영 설정에서 발견하지 못해 실전 비교는 미실시했다.

## 구현·검증·배포 결과

제품 코드 `ff74b90fcbebc70a5b47fc45ab3f313050ebc6fa`까지 구현했다.

  과거 PER·시세·종목 구분을 현재 값으로 바꾸지 않고, 매도 경로는 유지한다.

독립 최종 재검토는 승인됐다. 첫 전체 검증에서는 2,170건 통과·기존 관찰 모드

그 뒤 원천 적재와 보고서 생성을 수행하던 중 SSH·웹 응답 지연이 발생했다.

대상·기준일·최신 후보를 SQL에서 좁히고 나눠 읽는 보완과 별도 회귀 검증을 진행한다.
이미 커밋된 원천/검토가 있을 수 있어 적재를 무작정 재실행하지 않는다.

작업 중: 서버 복구·원인 확인, 적재 결과와 실제 v3 선별 결과를 아래에 확정한다.
새 기준이 매매 성과를 검증하거나 20거래일 시험 시작을 승인하지 않는다.

보고서 보완 커밋 `5fa3fb1`은 대상·기준일·관측/가용시점에 맞는 최신 후보 ID를
SQL에서 먼저 고르고 payload를 한 건씩 읽는다. 회귀 3건의 실패→통과를 확인했고,
관련 202건 통과 및 독립 검토 승인을 받았다. 최종 단독 전체 회귀는
`python scripts/run_isolated_tests.py`로 **2,255 passed, 기존 경고 24개, 549.27초**,
종료 코드 0을 확인했다. 이 보완은 master에 반영하며 운영 배포 전이다.
SSH는 연결 후 서버 인사 응답에서 시간 초과가 나고 HTTP도 응답하지 않는다.
AWS Lightsail 탭은 로그인 전이며, 사용자에게 직접 로그인을 요청했다.
인스턴스 재시작이나 AWS 설정 변경은 수행하지 않았다.

복구 후에는 아래 순서로 이어간다.

1. 호스트 메모리·부하와 커널 로그를 확인한다. 실행 중이면 이번 작업의
   `apply_observed_evidence.py` 프로세스만 식별해 종료한다. 전체 Python 프로세스를
   일괄 종료하지 않는다. OOM 여부는 로그로 확인하기 전까지 미확정이다.
2. 후보 payload 없이 종류별 건수와 EPS 원천/검토 ID·관측/가용시점만 조회한다.
   기대 대상은 공식 분류 2,738건, EPS 원천 39건, 검토 가능 25건이다.
   이 숫자는 적재 완료 확인값이 아니다. 기존 검토를 중복 등록하지 않는다.
3. 환경 파일·control·주문/체결 상태를 기준선과 비교한다. 실제 등록 시각을 유지하며
   다음 세션 가용일을 앞당기지 않는다.
4. 전체 검증이 통과한 보고서 보완 `5fa3fb1`을 배포한 뒤 제한된 보고서를 실행한다.
   실제 서버 자원 여유를 확인한 다음 v3 전체 선별을 실행하고 결과와 health를 검증한다.
5. 실제 선별 통과 여부, 남은 자료와 시세 조건을 갱신한다. 시험/거래 활성화는 하지 않는다.

## 운영 절차

일일 선별은 공식 종목 구분 수집 → 누락 EPS의 제한된 수집 → 연간 자료 수집 → v3 선별
순서로 진행한다. EPS와 연간 수집은 DART 요청·시간 한도를 공유한다. 수집 자체가 검토
승인이 되지는 않는다. 원문과 검토는 각각 변경 불가능한 증거로 보존한다.

`scripts/fujimoto_valuation.py`의 `report`로 미확인 사유를 확인하고, 검증 가능한 음수
보통주 EPS 원천만 `review`로 검토한다. `collect`, `ingest-eps`, `ingest-metadata`,
`review`는 명시적인 `--apply` 없이는 적재·승인을 수행하지 않는다. 원문, 기준연도,
종목-법인 대응, 접수번호와 재무제표 문맥이 맞지 않으면 현재 선별을 통과시키는 근거로
사용하지 않는다.

같은 원문을 다시 읽으면 최초 관측·검토를 재사용한다. 새로운 정정공시·기업 식별 변경·
재무 원문 변경은 기존 제외 근거를 무효화한다. 과거 원문을 다시 적재해도 최신의 독립적인
기업 식별 관측을 덮어쓰지 않는다. 과거 v1/v2 및 당시 근거를 고정한 재생 결과는 보존한다.
