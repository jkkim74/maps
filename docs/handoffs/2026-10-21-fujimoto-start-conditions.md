## 시세 지연과 수정

14:43:32 이후 실제 호가 10,912건 중 2,836건이 수신 후 기록까지 3초를 넘었다.
계좌 동기화 구간 중 수신된 4,394건 가운데 2,832건이 지연됐으며 p95는 13.563초였다.
그 밖에서는 6,518건 중 4건만 지연됐고 p95는 0.005초였다.
동기화 구간은 완료 로그 기준이며 후속 포트폴리오 처리도 포함하므로 정확한 잠금 보유 시간과 같지는 않다.

시세 원문 기록을 전용 스레드·독립 DB Session·256개 FIFO로 분리했다. 주문 처리는 기존 계좌 잠금으로 직렬화한다.
수신 원본 시각을 보존하며, 잠금·브로커 조회 후 실제 경과시간을 반영해 3초를 다시 검사한다.
구독 갱신 대기는 소켓 수신을 막지 않는다. 재접속 이전 시세와 기록 실패는 주문에 사용하지 않는다.
큐 포화 시 역압을 적용하며 원문을 조용히 버리지 않는다. 종료 시 기록·주문 작업을 함께 drain한다.
큐·계좌 잠금·후지모토 동기화 지연은 계좌 식별자 없이 제한된 빈도로 로그에 남긴다.

계좌 신선도 30초, 시세 신선도 3초, KIS 요청 간격 1.1초를 유지한다.
이 수정은 브로커 응답 자체를 빠르게 하거나 오래된 계좌 정보를 새것으로 바꾸지 않는다.
장중 실제 지연과 계좌 신선도는 다음 실제 거래 세션에서 다시 확인해야 한다.

변경 소스는 `maps/limit_up/runtime.py`, `maps/fujimoto/feed.py`, `maps/fujimoto/service.py`,
`maps/execution/safety.py`, `maps/execution/order_manager.py`다.
회귀 테스트 `tests/test_fujimoto_feed_latency.py`와 해당 패키지의 `CLAUDE.md`, 실행 계획·인계 문서를 함께 갱신했다.
