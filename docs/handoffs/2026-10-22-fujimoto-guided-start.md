# 후지모토 모의시험 시작 안내 화면 — 2026-10-22

## 변경 목적과 구현

사용자가 유효 후보 발생 후 해야 할 행동을 알 수 없다고 지적해, 승인한 흐름대로
기존 화면을 `예산 확인 → 자동 준비 점검 → 동의·시작 승인 → 진행 확인`으로 정리했다.
기능 커밋은 `f940ded`, 주 작업 폴더 통합 커밋은 `c0408ab`이다.

- 상단에 현재 단계, 지금 할 행동, 해당 단계 이동, 최근 성공 조회 시각을 표시한다.
- 저장 총예산과 각 모드 배분을 명시하고, 변경이 없으면 재저장이 불필요함을 안내한다.
  예산·호가 설정 저장이 신규 진입을 중지시킨다는 경고는 저장 버튼 바로 앞에 둔다.
- 준비 사유를 사용자 확인, 자동 수집·선별·호가, 운영자·기타 확인으로 구분한다.
  후보가 있어도 운영 조건이 막혀 있으면 승인 가능으로 표시하지 않는다.
- 준비 완료 시 동의·승인 단계로 안내한다. 예약·진행·중지·만료 상태는 진행 확인으로
  안내하며, 실제 날짜·차단 사유를 유지한다. 종목 선택과 분할매매는 자동임을 설명한다.
- 원문 기반형의 가격 손절 없음과 새 취득분에 한정한 자동 청산 동의를 유지했다.
- 별도 측정 검증 기반 활성화는 기본 닫힌 고급 설정으로 옮겼다. 후보 미통과와 자료
  미확인을 구분하고 주요 차단 코드를 한국어로 표시한다.
- 화면이 보이는 동안 15초 간격으로 기존 읽기 API만 조회한다. 입력 중 값을 보존하고,
  중복 읽기와 쓰기 전 오래된 응답의 덮어쓰기를 막는다. 일부 조회라도 실패하면 즉시
  시작 버튼을 잠그며, 실제 성공 조회 이후에만 준비 안내를 회복한다.

수정 파일은 `templates/fujimoto.html`, `tests/test_fujimoto_ui.py`, `maps/api/CLAUDE.md`와
[설계](../superpowers/specs/2026-10-22-fujimoto-guided-start-design.md),
[실행 계획](../superpowers/plans/2026-10-22-fujimoto-guided-start.md)이다.
API 계약·매매 규칙·스키마·의존성은 변경하지 않았다.

  **99 passed (33.18초)**. 실패 테스트를 먼저 확인하고 구현했다.

  81 passed / 2.92초였다. 배포 폴더와 시험한 제품 파일의 동일성을 확인했다.

  충돌을 보고했다. 화면을 읽거나 캡처하지 못했으므로 데스크톱·좁은 화면 통과를 주장하지 않는다.
  실제 운영 승인 버튼은 누르지 않았다.

## 운영 반영과 남은 조건

**11:12:30 KST `c0408ab` 운영 반영·서비스 재기동 완료.** 별도 깨끗한 배포 폴더에서
원격 master로 반영했으며 운영의 추적 파일 변경 없음, 분석 작업 미실행과 배포 시간대를
확인했다. 내부·외부 `/health` 200, 서비스 active, 운영 템플릿 blob이 검증본과 동일했다.

배포 전후 읽기 전용 점검을 비교해 환경 파일 지문·설정·control·시험 상태·주문 수가
모두 동일함을 확인했다. 상태는
`control_id=100760`, 관찰 모드, 신규 진입·동의 false, 전역 주문 실행 false,
실거래 false, 모드별 예산 500만원, 모의시험 미시작, 후지모토 주문·체결 0건이었다.
배포 후에도 남은 차단 사유는 최신 구독 호가 없음, 주문 실행 스위치 꺼짐, 유효 후보 근거 없음이다.

화면 개선은 실제 시험 시작이나 거래 허용을 뜻하지 않는다. 장 마감 자료 수집·선별,
유효 후보와 최신 실제 호가·계좌 근거, 운영자의 모의 주문 설정 확인, 사용자의 명시적인
동의·시작 승인이 여전히 필요하다. 오전 자료 보완과 예정 작업은
[오전 인수인계](2026-10-22-per-morning-resume.md)를 따른다.
