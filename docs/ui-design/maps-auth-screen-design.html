등급별 메뉴 구성

셸은 세 등급 모두 같다 — 사이드바 280px + 상단바 56px + 본문. 메뉴 항목만 달라진다. 무료 7개, 유료 11개, 관리자 24개.

세 사이드바를 나란히 놓으면 등급이 올라갈 때 무엇이 붙는지가 보인다. 무료 → 유료는 내 계좌 섹션 4개가 붙고, 유료 → 관리자는 운영·검증 화면 17개가 붙는 대신 내 계좌가 내 계좌 연결 하나로 줄어든다(운영자는 서버 .env 계좌를 쓴다).

규칙

  • 섹션에 남는 항목이 0개면 섹션 라벨까지 숨긴다. 무료·유료에게 「검증 · 견고성」이 제목만 덩그러니 남으면 안 된다.
  • 메뉴 번호는 숨겨도 재부여하지 않는다. 무료 사용자에게는 03 04 18 19 20 처럼 띄엄띄엄 보인다. 운영자와 같은 화면을 가리키는 식별자이므로 일부러 유지한다 — 문의를 받을 때 같은 번호로 대화할 수 있다.
  • 내 계좌 섹션은 번호 대신 ◈ 기호를 쓴다. 운영 화면(번호)과 내 계좌 화면(기호)이 시각적으로 구분돼야 한다.
  • 상단바: 화면명 · 새로고침 · 아이디 · 등급배지 · 로그아웃. 등급배지는 무료 유료 관리자.
  • 시작 화면: 관리자 /dashboard, 유료 /my/trading, 무료 /stock-analysis. 개인 설정 landing_screen 이 있으면 그쪽이 우선.
  • 일반 사용자가 / 로 들어오면 대시보드를 렌더하지 않고 시작 화면으로 303 리다이렉트한다. 대시보드는 운영자 계좌 잔고를 그린다.
숨김은 편의일 뿐, 통제가 아니다

사이드바에서 빠진 화면도 주소를 직접 입력하면 요청은 서버에 도달한다. 실제 차단은 auth_gate_middleware 가 하며, 메뉴를 숨기는 이유는 "쓸 수 없는 것을 보여 주지 않기 위해서"다. 두 장치가 같은 판정 함수 is_allowed() 를 쓰도록 구현해야 어긋나지 않는다.

무료 사용자가 유료 경로에 닿았을 때는 403이 아니다

/my/trading 같은 유료 경로에 무료 사용자가 접근하면 권한 거부가 아니라 업그레이드 안내를 보여 준다. 권한이 없는 게 아니라 등급이 낮은 것이고, 이때는 "무엇을 하면 쓸 수 있는지"를 알려 주는 편이 맞다. 화면은 AUTH-03 과 다르게 만든다.

임의 키를 만들 수 없다

여기서 추가란 get_config_status() 에 정의돼 있으나 아직 비어 있는 항목에 값을 넣는 것을 말한다. 정의되지 않은 이름을 화면에서 만들 수 있게 하면 오타 하나로 다음 기동이 깨진다. 편집 대상은 59개 허용목록으로 고정하고, 목록에 없는 키는 서버가 400 으로 거절한다.

비활성화는 즉시 효력이 있다

역할·상태를 세션이나 모바일 토큰에 굽지 않고 매 요청 DB에서 다시 읽는다. 비활성화하면 이미 로그인한 세션과 발급된 토큰이 그 즉시 막힌다 — 화면 문구에 이 사실을 적어 관리자가 “로그아웃될 때까지 기다려야 하나”를 묻지 않게 한다.

F · 비밀 항목 규칙

운영 설정 59개 중 15개가 비밀 항목이다 — MAPS_DB_URL, KIS_APP_KEY, KIS_APP_SECRET, KIS_ACCOUNT_NO, KIWOOM_ACCOUNT_NO, KIWOOM_PASSWORD, DART_API_KEY, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, NAVER_CLIENT_ID, NAVER_CLIENT_SECRET, SLACK_WEBHOOK_URL, TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET, MAPS_FCM_SERVICE_ACCOUNT_PATH.

  • 조회 시 마스킹해서 내려보낸다. 평문을 응답에 싣지 않는다.
  • 저장 후 재열람 불가 — 화면은 “다시 볼 수 없습니다”를 입력칸 옆에 표시한다.
  • 감사 로그에는 값 없이 변경됨만 남긴다.
  • 비밀번호·자격증명이 예외 메시지로 로그에 섞이지 않는지 확인한다(2026-08-11 실제 사고).
