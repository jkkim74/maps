# 미국주식 모의매매 화면설계서

- 문서 ID: `US-UI-001`
- 버전: v0.1
- 작성일: 2026-10-16
- 상태: 설계 산출물 — 화면 구현·검수 완료를 의미하지 않음
- 메인 화면: `/us-trading`
- 메뉴명: **미국주식 모의매매**
- 사용자: 관리자
- 관련 문서: [프로그램 구현 목록](../us-trading-program-list.md)

기존 MAPS 내비게이션·색상·카드·테이블을 재사용한다. 루트 `templates/`의 서버 템플릿으로 구현하며 모바일 앱 확장은 제외한다. 첫 버전은 정규장·USD·정수 수량·지정가·허용 종목만 지원한다.

## 3. US-S01 — 계좌·운영 상태

| 요소 | 표시·동작 |
|---|---|
| 환경 배지 | `로컬 모의` 또는 `KIS 모의`. 실거래 전환 버튼 없음 |
| 계좌 표시 | 마스킹한 미국 전용 계좌 |
| 시장 상태 | 정규장 전·정규장·장 종료·휴장·확인 불가 |
| 거래일·시각 | 미국 거래일 명시, 시각에는 ET/KST 구분 표시 |
| USD 현금 | 실제 조회 현금. 주문 가능액과 구분 |
| 주문 가능액 | 계좌 공통 금액을 제공하지 못하면 종목 선택 후 조회하도록 안내 |
| 마지막 동기화 | 완료 시각과 데이터 경과 시간 |
| 상태 안내 | 신규 매수 가능 여부와 차단 사유 표시 |
| 동기화 | 백그라운드 작업 요청. 실행 중 중복 요청 제한 |
| 신규 매수 중단 | 신규 매수 차단. 기존 주문을 취소하거나 보유분을 매도하지 않음 |
| 중단 해제 | 수동 중단만 해제하며 나머지 안전 조건은 재검사 |

화면 자동 갱신은 저장된 최신 상태를 조회한다. 브라우저마다 KIS 조회를 발생시키지 않는다. 화면 표시는 실행 권한의 근거가 아니며 주문 제출 시 서버가 최신 상태를 다시 검사한다.

연결 API: `GET /status`, `GET /account`, `POST /sync`, `POST /entry-stop`, `POST /entry-resume`.

## 4. US-S02·S03 — 주문 입력 및 확인

| 입력 항목 | 입력 방식 | 검증 |
|---|---|---|
| 종목 | 허용 목록 검색·선택 | 미등록·거래소 미확인 종목 차단 |
| 거래소 | 종목 정보에 따라 표시 | 사용자가 임의 변경하지 못함 |
| 방향 | 매수/매도 | 매도는 귀속·승인 범위 검사 |
| 수량 | 양의 정수 | 소수·0·음수·매도 가능 수량 초과 차단 |
| 지정가 | USD 소수 금액 | 양수 및 시장 가격 단위 검사 |
| 주문 금액 | 수량 × 지정가 | USD 표시. 수수료 포함 여부 명시 |
| 주문 출처 | `관리자 수동` 고정 | 전략 출처 선택 기능 없음 |

### 주문 흐름

1. 관리자가 주문 조건을 입력한다.
2. `주문 검토`로 서버 사전 검사를 요청한다.
3. 확인 창에 계좌·종목·방향·수량·가격·금액·검사 결과를 표시한다.
4. `모의 매수 제출` 또는 `모의 매도 제출`을 누르면 최신 조건을 다시 검사한다.
5. 제출 후 주문 상세를 표시하고 체결 추적을 시작한다.

### 확인 창 규칙

- 매도에는 **해당 수량의 매도 승인**을 명시한다.
- 확인 창을 닫거나 입력을 변경하면 이전 검토 결과를 폐기한다.
- 제출 중에는 중복 클릭을 막고 같은 요청 ID를 유지한다.
- 응답 단절 시 “주문 결과 확인 중입니다. 같은 주문을 다시 제출하지 마세요.”를 표시한다.
- 주문 접수 성공을 체결 완료로 표시하지 않는다.
- 미리보기는 주문 제출이나 자금 예약을 수행하지 않는다.

연결 API: `GET /quotes`, `POST /orders/preview`, `POST /orders`.

## 5. US-S04·S05 — 주문 목록·상세·취소

주문 목록 필터: 미국 거래일 범위, 종목, 방향, 상태, 주문 출처.

| 목록 열 | 내용 |
|---|---|
| 주문 시각 | 시간대 명시 |
| 종목·거래소 | 주문 대상 |
| 방향·출처 | 매수/매도, 수동 또는 향후 전략명 |
| 수량 | 주문·체결·잔량 |
| 가격 | 지정가·평균 체결가, USD |
| 상태 | 접수 대기·미체결·부분체결·체결 완료·취소·거절·결과 불명 |
| 동작 | 상세 보기, 조건부 취소 요청 |

상세 패널에는 요청 ID, 브로커 주문번호, 계좌·환경, 주문 근거, 체결 누계, 비용 확인 여부, 취소 진행 상태, 감사 이력을 표시한다. 향후 전략 주문은 전략 ID·버전·실행 인스턴스로 구분한다.

### 취소 규칙

- 잔량과 정확한 주문 식별자를 확인한 경우에만 취소 요청을 허용한다.
- 취소 확인 창에는 종목·잔량·현재 상태를 표시한다.
- 취소 요청 후에도 체결이 발생할 수 있음을 안내한다.
- 취소 접수 단계에서는 `취소 확인 중`을 표시한다.
- 미확정 주문을 임의로 완료 처리하는 버튼은 제공하지 않는다.

연결 API: `GET /orders`, `GET /orders/{id}`, `POST /orders/{id}/cancel`.

## 6. US-S06 — 보유 현황

| 항목 | 설명 |
|---|---|
| 종목·거래소 | 보유 대상 |
| 브로커 보유 수량 | 계좌에서 확인한 실제 수량 |
| 실행 출처·인스턴스 | 수동 거래 또는 향후 전략 귀속 |
| 귀속 수량 | 해당 인스턴스의 확인된 체결 기준 수량 |
| 매도 예약 수량 | 미확정 매도 주문에 예약된 수량 |
| 매도 가능 수량 | 브로커 가능 수량과 귀속·예약 조건을 함께 반영 |
| 평균 매입가·현재가 | USD, 관측 시각 포함 |
| 평가손익 | 확인 가능한 범위만 표시하고 비용 미확정 여부 명시 |
| 대사 상태 | 일치·불일치·미확인 |
| 동작 | 허용된 보유분의 매도 입력으로 이동 |

외부 보유분은 `미귀속 보유`로 표시한다. 첫 버전에서는 자동 편입이나 해당 보유분 매도 기능을 제공하지 않는다. 같은 종목에 여러 실행 인스턴스가 연결되더라도 브로커 총보유 수량을 중복 합산하지 않는다.

연결 API: `GET /positions`.

## 7. US-S07 — 대사·운영 이력

| 요소 | 내용 |
|---|---|
| 대사 요약 | 최근 실행·성공 시각, 주문·잔고 확인 상태 |
| 차단 사유 | 시세 노후, 주문 결과 불명, 잔고 불일치, 한도 초과 등 |
| 이벤트 목록 | 시각, 유형, 관련 주문, 처리자, 결과 |
| 수동 동기화 | 동일한 공통 대사 작업 요청 |
| 복구 안내 | 자동 확인 중인지, 관리자가 근거를 확인해야 하는지 구분 |

자격증명·전체 계좌번호·토큰·민감한 원본 응답은 화면과 로그에 노출하지 않는다.

연결 API: `GET /status`, `GET /events`, `POST /sync`.

## 8. 공통 상태·오류 표시

| 상황 | 표시 | 허용 동작 |
|---|---|---|
| 설정 누락 | “미국 모의계좌 설정이 필요합니다.” | 상태 조회 |
| 정상 조회, 보유 없음 | “보유 종목이 없습니다.” | 조건 충족 시 주문 |
| 조회 실패 | 오류와 마지막 성공 시각 표시 | 재조회 |
| 시세 미확인 | 가격 `—`, 사유 표시 | 신규 주문 차단 |
| 계좌 대사 불일치 | 불일치 내용과 신규 매수 차단 표시 | 조회·대사, 안전 조건을 충족한 매도·취소 |
| 주문 결과 불명 | 결과 확인 중, 예약 유지 표시 | 조회·대사 |
| 신규 매수 중단 | 중단 사유·처리자·시각 표시 | 조회, 조건부 매도·취소 |
| 권한 없음 | 접근 거부 | 주문·계좌 데이터 노출 없음 |

로딩·빈 결과·조회 실패를 구분하고, 상태는 색상과 문구를 함께 사용한다. 확인 창은 키보드 조작과 초점 복귀를 지원한다.

모든 API의 기본 경로는 `/api/v1/us-trading`이다. 화면에서 버튼을 비활성화해도 서버 검증을 생략하지 않는다. 미로그인 사용자는 기존 인증 흐름을 따르고, 일반 사용자의 화면·API 접근은 차단한다.

## 9. 화면 검수 기준

- 모든 주문 화면에서 모의환경·미국 계좌·USD 단위를 식별할 수 있다.
- 주문 검토 후 잔고나 시세가 바뀌면 제출 단계에서 다시 검사한다.
- 중복 클릭·응답 단절·부분체결·취소 진행 상태를 구분해 표시한다.
- 미확인 금액이나 손익을 `0`으로 표시하지 않는다.
- 화면을 새로 열어도 서버에 저장된 주문 상태를 복원한다.
- 일반 사용자는 URL 직접 접근과 API 호출 모두 차단된다.
- 향후 전략 주문도 기존 목록·상세·보유 화면에서 출처와 버전으로 구분할 수 있다.
- 신규 매수 중단은 기존 주문 취소·보유분 청산으로 동작하지 않는다.

화면 구현 후 정상 상태, 주문 차단, 주문 확인, 부분체결·취소 확인 중, 결과 불명, 조회 실패의 스크린샷을 검수 자료로 남긴다.

## 10. 구현 현황

US-S01~US-S07은 `/us-trading`의 `templates/us_trading.html`과 `static/js/us-trading.js`로 구현했다. 템플릿 렌더링 및 주문 확인·매도 동의·응답 단절·결과 불명·재조회 이벤트는 자동 테스트로 검증했다. 브라우저 확장 프로그램이 자동화를 차단해 스크린샷과 시각적 배치 검수는 미완료다. 검증 결과와 제한은 [ExecPlan](../superpowers/plans/2026-10-16-us-paper-trading.md)에 기록한다.
