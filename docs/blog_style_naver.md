# 네이버 블로그 원고 규약

MAPS 가 만드는 블로그 원고는 **네이버 스마트에디터에 그대로 붙여넣어 발행**하는 것을
전제로 한다. 자동 발행은 하지 않는다 — 사람이 복사해서 붙인다.

스마트에디터는 **마크다운을 렌더링하지 않는다.** `##`, `**`, `` ` ``, `|표|` 는
기호 그대로 본문에 노출된다. 그래서 원고는 마크다운이 아니라 **평문(`.txt`)** 으로 쓴다.

규약은 두 갈래다.

- **1~2절 (붙여넣기)** — 지키지 않으면 글이 깨진다.
- **3절 (문체)** — 지키지 않으면 AI가 쓴 글로 읽힌다. 투자 글에서는 이쪽이 더 치명적이다.

`docs/strategy_guides/*.txt` 8편이 이 규약을 전부 지키는 본보기다. 새로 발명하지 말고
그 파일들을 먼저 읽는다.

---

## 1. 쓰지 않는 것 (붙여넣기)

| 금지 | 붙여넣으면 |
|---|---|
| `# 제목` `## 소제목` | `##` 이 그대로 보인다 |
| `**굵게**` `*기울임*` | `**` 이 그대로 보인다 |
| `` `코드` `` ```` ```블록``` ```` | 백틱이 그대로 보인다 |
| `\| 표 \| 헤더 \|` + `\|---\|` | 파이프와 대시가 줄줄이 노출된다. **가장 심하게 깨진다** |
| `--- ` (하이픈 3개) | 구분선이 되지 않고 하이픈으로 남는다 |
| `> 인용` | `>` 가 그대로 보인다 |
| `[텍스트](url)` | 대괄호·괄호가 그대로 보인다 |
| YAML 프론트매터 | 본문 맨 위에 `ref_date: ...` 가 노출된다 |

## 2. 쓰는 것 (붙여넣기)

**섹션 헤더** — `─`(U+2500) 20자 구분선 사이에 번호 + 제목

```
────────────────────
1. 오늘의 결론
────────────────────
```

> **2026-07-31 실붙여넣기 실측으로 정정.** 이전 규약은 33자였고 "모바일에서
> 줄바꿈되지 않는 상한"이라고 적혀 있었으나, 스마트에디터에 실제로 붙여넣으니
> **접혔다.** 본문 줄·들여쓰기·원문자·가운뎃점은 33자 시절 그대로 정상이었고
> 구분선만 문제였다. 20자로 내렸다.
>
> 33자는 붙여넣어 보지 않고 계산으로 정한 값이었다. `─` 는 전각이라
> 같은 글자 수의 한글 본문보다 실제 폭이 넓다. **본문 30자가 안 접힌다고
> 구분선 30자가 안 접히는 게 아니다.**
>
> `docs/strategy_guides/*.txt` 9편(구분선 160개)도 같은 날 20자로 내렸다.
> 본보기가 규약을 어기면 규약이 무의미해진다. 산문은 건드리지 않았다.

**강조** — `【 】`, `▶`. 굵게·색은 붙여넣은 뒤 에디터에서 직접 지정한다.

**목록** — `·` `▸` `①②③` `㉠㉡`, 들여쓰기 2칸

```
▶ 장점
  · 손절 폭이 좁아서 한 번 틀렸을 때 손실이 작습니다
  · 보유 기간이 짧아 자금이 오래 묶이지 않습니다
```

**표는 만들지 않는다.** 두 가지 중 하나로 편다.

```
▸ 082640 · donchian_v1 · 636주 · 8,180원 체결      ← 한 줄에 이어 쓰기
```

```
  단기 이동평균     : 5일                          ← 라벨:값 세로 나열
  장기 이동평균     : 20일
```

세로 나열은 **라벨을 한글로 통일하고 글자 수를 맞출 때만** 정렬이 유지된다.
네이버 기본 폰트가 가변폭이라 한글·영문을 섞으면 어긋난다.
`ATR 배수`처럼 영문이 섞이면 정렬을 포기하고 한 줄 이어쓰기를 쓴다.

**빈 줄은 문단 사이 1줄, 섹션 구분선 앞 2줄까지.** 3줄 연속은 쓰지 않는다.
붙여넣으면 각 줄이 문단이 되어 간격이 이미 넓다.
(가이드 8편 실측: 2줄 연속 101회, 3줄 연속 0회)

**한 줄은 30자 안팎, 길어도 50자.** 네이버 앱에서 그 이상은 임의로 접힌다.
전략 ID·티커가 들어가는 줄은 더 길어져도 어쩔 수 없다.
(가이드 8편 실측: 중앙값 29자, 상위 10% 38자, 최대 62자)

## 3. 문체 — AI가 쓴 티를 없앤다

깨지지는 않지만 이쪽이 더 중요하다. 투자 글에서 "AI가 찍어낸 글" 로 보이는 순간
숫자의 신뢰도까지 같이 떨어진다.

**이모지를 쓰지 않는다.** 한 개도. 섹션 헤더는 번호로 구분한다(2절).
`✅` `⚠️` `★` `✓` 같은 기호도 이모지다. 구분선 `─`, 화살표 `▶` `▸`,
가운뎃점 `·`, 원문자 `①` 는 기하 문자라 써도 된다.

**em dash(`—`)를 쓰지 않는다.** AI 글의 가장 흔한 지문이다.
쉼표, 마침표, 줄바꿈, 괄호로 대신한다. (구분선 `─` 와는 다른 문자다)

**상투구를 쓰지 않는다.** 자리만 차지하고 정보가 없는 말들이다.

> 결론적으로 / 종합적으로 / ~라고 할 수 있습니다 / 주목할 필요가 있습니다 /
> 알아보겠습니다 / 살펴보겠습니다 / ~하시기 바랍니다 / 여러분

**리듬을 고르게 만들지 않는다.** AI 글은 문단 길이와 문장 길이가 균일하다.

- 한 문장짜리 문단을 섞는다
- 모든 섹션을 같은 분량으로 채우지 않는다. 쓸 게 없으면 두 줄로 끝낸다
- 목록 항목 수를 3개로 맞추려 하지 않는다
- 숫자를 나열한 뒤 매번 해설을 붙이지 않는다. 숫자만 남기고 넘어가도 된다

**요약을 두 번 하지 않는다.** 서두에 요약했으면 말미에 또 하지 않는다.

**완충 표현 대신 단정한다.** "~인 것으로 보입니다" 보다 "~였습니다".
모르면 "확인하지 못했습니다" 라고 쓴다. 얼버무리는 것보다 낫다.

**해석을 덧붙이지 않아도 된다.** 규칙이 X였고 조건이 Y라서 Z했다,
로 끝나는 문단이 가장 신뢰가 간다. 교훈이나 다짐으로 마무리하지 않는다.

## 4. 초보자용 매매 기록 문체

SCR-20 일일 매매 기록의 앞부분은 주식 초보자가 읽는 설명 영역이다. 전문용어는 쉬운 뜻을
먼저 쓰고 원래 용어를 괄호에 둔다.

```
좋음: 상승과 하락 신호가 섞인 시장(MIXED)
나쁨: 오늘은 MIXED 국면이다.
```

처음 등장할 때는 아래 표현을 그대로 쓴다. 같은 원고에서 반복될 때는 쉬운 표현만 써도 된다.

| 원래 용어 | 첫 등장 표현 |
|---|---|
| `STRONG` | 상승 흐름이 뚜렷한 시장(STRONG) |
| `MIXED` | 상승과 하락 신호가 섞인 시장(MIXED) |
| `WEAK` | 하락 압력이 큰 시장(WEAK) |
| `LOW` 변동성 | 가격 움직임이 평소보다 작은 상태(LOW 변동성) |
| `NORMAL` 변동성 | 가격 움직임이 평소 수준인 상태(NORMAL 변동성) |
| `HIGH` 변동성 | 가격 움직임이 평소보다 큰 상태(HIGH 변동성) |
| `Breadth` | 오르는 종목의 비율(Breadth) |
| `entry limit` | 오늘 허용된 최대 신규매수 비율(entry limit) |
| `filled` | 주문 수량이 모두 거래된 상태(filled) |
| `partially filled` | 주문 수량 중 일부만 거래된 상태(partially filled) |
| `stop loss` | 손실 제한 가격에 도달한 매도(stop loss) |
| `take profit` | 목표 가격에 도달한 매도(take profit) |

숫자는 오늘 행동에 준 의미를 한 번만 설명한다. 손익만으로 좋은 거래·나쁜 거래를 판정하지
않고 계획한 규칙이 실행됐는지만 적는다. 미측정·누락·수집 실패는 추정으로 메우지 않는다.

`6. 상세 기록`은 원시 값과 식별자를 보존하는 감사 영역이다. 이 영역은 쉬운 본문 용어
검사 대상이 아니며, 앞에서 설명한 원래 용어와 코드를 그대로 쓸 수 있다.

## 5. 파일 구조

제목과 태그는 스마트에디터에서 **입력란이 따로 있다.** 본문에 섞으면 지워야 하므로
파일 맨 위·맨 아래에 분리해 둔다.

```
제목: MAPS가 오늘 신규 매수를 전면 중단한 이유

(본문)

태그: AI주식투자 자동매매 퀀트투자 시장국면 백테스트
```

## 6. 검사

`scripts/check_naver_format.py` 가 이 규약의 **유일한 구현**이다.
셸과 파이썬에 패턴을 따로 두면 한쪽만 고쳐지고 조용히 어긋난다.

```powershell
python scripts/check_naver_format.py blog\2026-07-29.txt
python scripts/check_naver_format.py --paste-only <원고>   # 1~2절만
```

검사기는 이모지, em dash, 상투구와 SCR-20 쉬운 본문의 핵심 전문용어의 쉬운 설명 누락까지 검사한다.
리듬·요약 중복·완충 표현은 기계로 판단하지 않고 사람이 읽어 확인한다.

저녁 배치(`run_blog_cron.sh` 4단계)가 생성 직후 자동으로 돌리고, 위반 목록을 로그에 남긴다.
배치를 실패시키지는 않는다. 발행 전에 사람이 보고 고치면 되기 때문이다.
