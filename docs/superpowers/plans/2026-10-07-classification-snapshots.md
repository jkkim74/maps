## Global constraints and shared interfaces
- Python 3.11+, existing requests/SQLAlchemy/pytest only. Read index -> package CLAUDE -> code. Keep docs current. Tests use isolated SQLite and fake HTTP/broker; never network in tests.
- Shared verification: `D:/workspace/maps/maps/maps/.venv/Scripts/python.exe scripts/run_isolated_tests.py <tests> -q --tb=short`, PYTHONUTF8=1.
- Immutable snapshot model, two new tables: ClassificationRun and ClassificationMember. Run fields: id, kind (sector/theme), provider, ref_date, status (running/complete/partial/failed/missed), started_at, finished_at, published_at nullable, expected_tickers JSON list, catalog JSON {code:name}, metrics JSON, error nullable, notified_at nullable. Member fields: run_id FK, ticker, code, name, unique(run_id,ticker,code). A complete published run plus membership in expected_tickers proves a zero-membership ticker is verified no-theme; absence from the universe is unknown. Sector must have exactly one value for every expected ticker.
- Preserve historical code/name with each snapshot. Sector codes use the returned KRX label until upstream supplies a distinct stable code. Existing SecurityMetadata.sector remains a compatibility projection, theme stays legacy only. No fabricated historical backfill.
- New `maps/data/classifications.py`: `ClassificationPayload` dataclass fields kind:str, provider:str, ref_date:date, expected_tickers:list[str], catalog:dict[str,str], memberships:dict[str,list[str]], metrics:dict (default factory), error:str|None=None. Membership values reference catalog codes; an empty list explicitly denotes no theme. `ClassificationRepository(db)` methods `start(kind,provider,ref_date)->ClassificationRun`, `publish(run,payload)->ClassificationRun` (validate and atomically insert immutable members + mark complete/published; commits), `fail(run,error,status='failed',metrics=None)->ClassificationRun` (commits), `latest(kind,ref_date=None,available_at=None)->ClassificationRun|None` (published complete only, exact ref_date if provided; published_at<=available_at), `memberships(run,tickers=None)->dict[str,set[str]]` (seed expected tickers as empty sets), `theme_names(run)->dict[str,str]`. All timestamps UTC naive in DB; normalize aware inputs. Failed attempts never supersede published runs. Publish validates nonempty distinct universe, nonempty catalog, no unexpected ticker or unknown codes, and sector coverage. Snapshot currentness is exact expected trading day, not generic row.updated_at.
- Npay adapter `maps/data/naver_themes.py`: `NaverThemeAdapter(session=None, timeout=10, deadline_seconds=1200, sleep=..., monotonic=...)`; method `collect(ref_date,expected_tickers)->ClassificationPayload`. Live JSON endpoints observed: https://stock.naver.com/api/domestic/market/theme/list?startIdx=PAGE&pageSize=200&sortType=changeRate and /theme/{no}/stocklist?marketType=ALL&orderType=marketSum&startIdx=PAGE&pageSize=200. PAGE is zero-based PAGE NUMBER, not row offset. Catalog response list fields no,name,totalCnt; members list itemcode,itemname. Catalog is currently 264 entries; never hardcode count. Validate entire source member counts BEFORE filtering to expected universe. Start/end manifest (code,name,totalCnt) must match. Full-universe zero assigned themes is a failure. Request timeout, bounded retries for transient failures, >=0.25s request spacing, wall deadline checked before/after requests. No fallback/inferred labels. Do not interpret thistime (quote time) as classification-change time.
- Ops settings owned by Task3: maps_theme_collection_enabled=False, maps_theme_collection_time='17:00', maps_classification_check_time='17:25', maps_classification_snapshot_enforced=False. Disabled collector produces visible disabled status, never an unnoticed missed alert. Feature flags allow schema/collector-first rollout before risk switch. When enforced=False preserve existing single-column risk behavior; when True sector+theme snapshot policy applies only to nonexempt contexts. No settings changes to production.
