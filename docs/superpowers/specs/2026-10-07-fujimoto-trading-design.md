## 1. 검토 결론과 확정 범위

구축은 가능하다. 다만 새 전략 하나를 추가하는 수준이 아니라 분할매매 상태 관리와 검증 엔진 확장이 필요하다.

블로그는 우량주 선별, 기술적 지표 확인, 1:2:6 분할매매를 결합한다. 본문과 관심종목 체크리스트·지표 대응표 이미지를 확인했다. 글에서도 지표별 매매 조건은 저자가 재구성한 규칙이라고 명시한다. 시스템은 **후지모토 원칙을 참고한 MAPS 전략**으로 정의한다. 블로그가 인용한 서적·인터뷰 전체를 직접 검증한 것은 아니다.

### 사용자 선택으로 확정한 범위

- 한국 주식 전 시장에서 정량 조건으로 자동 선별한다.
- 일봉·주봉 신호와 장중 호가를 이용한 자동매매까지 설계한다.
- 안전형과 원문 기반형을 동일 계좌에서 동시에 운영한다.
- 전략 예산은 기본 50:50으로 분리하고 계좌 공통 위험 한도를 우선한다.
- 안전형은 반전 확인 후 추가 매수한다. 원문 기반형은 실적 유지 시 하락 추가 매수도 허용한다.
- RSI 14, MACD 12/26/9, 일목 9/26/52, 1차 일 RSI≤40·주 RSI<70, 매수가 상한=신호일 종가, 호가 익절=수익 중 매수잔량/매도잔량≥3이 30초 지속을 **검증 전 가설**로 사용한다.

원문 기반형에도 계좌 한도와 자동 종목 선별을 적용하므로 원문을 완전히 재현하는 것은 아니다. 화면과 보고서에는 ‘원문 기반·계좌 한도 적용형’으로 표시한다. ‘사업 이해도’는 자동 통과 조건으로 만들지 않고 설명 자료에 표시한다.

아래 세부 기본값 중 사용자 선택 목록에 없는 수치는 설계자가 제안한 연구 기본값이다. 후지모토 본인의 공식이나 실증 완료 값으로 취급하지 않는다. 설계 저장과 git push 요청은 실거래 활성화나 기존 보유분 청산 승인이 아니다.

### 위험 해석

블로그의 68% 하락은 손실 상한이 아니다. 제시한 배분대로 초기 자산의 13.5%씩 다섯 종목을 보유하고 모두 68% 하락하면 계좌 손실은 45.9%다. 같은 배분에서 다섯 종목의 전액 손실은 67.5%다. 추가 현금 투입 전의 단순 스트레스 계산이며, 두 모드 동시 운영의 실제 손실 예측은 아니다. 이를 포트폴리오 스트레스 시나리오로 검증한다.

## 2. 매매 규칙과 위험 정책

### 종목 선별과 지표

| 항목 | 첫 버전 규칙 |
|---|---|
| 대상 | KOSPI·KOSDAQ 보통주. 기존 거래정지·관리종목·상장이력·유동성 검사 통과 |
| 실적 | 최근 확정 연간 실적 3개년에서 매출·영업이익이 두 번 연속 증가하고 영업이익이 양수 |
| 배당 | 같은 기간 주당배당금이 양수이고 감소하지 않음 |
| 가격 수준 | 양수 PER이 당시 동일 업종의 양수 PER 중앙값 이하 |
| 급등 제외 | 최근 20거래일 상승률 20% 초과 종목 제외 |
| 후보 우선순위 | 통과 종목의 20일 평균 거래대금 내림차순, 동률은 종목코드순 |
| 지표 | RSI 14, MACD 12/26/9, 일목 9/26/52 |
| 계산 시점 | 완성된 일봉과 주봉만 사용. 진행 중인 주봉을 과거 날짜에 소급하지 않음 |
| 결측 | 재무·배당·업종·가격 근거 부족은 신규·추가 매수 차단 |

배당 및 급등 제외 기준의 주변값도 민감도 검사 대상에 포함한다. 현재 종목 목록이나 업종을 과거 유니버스로 소급하지 않는다.

### 분할매수

1:2:6은 **매수 금액 비율**이다. 주가가 달라지므로 매수 수량 비율과 구분한다.

| 단계 | 안전형 | 원문 기반형 |
|---|---|---|
| 1차 | 일 RSI≤40, 주 RSI<70, 종목 선별 통과 | 동일 |
| 2차 | 1차 이후 일 MACD 골든크로스 또는 전환선의 기준선 상향 돌파 | 안전형 조건 또는 1차 체결가보다 하락하고 주 RSI가 30 이상 40 미만이며 실적 유지 |
| 3차 | 일목 세 조건 충족, 주 MACD선과 히스토그램 모두 전주보다 상승 | 동일 |
| 가격 손절 | 공용 손절 계산: 초기 가설 고정 8%, ATR 3배, 손절폭 상한 16% | 가격 손절 없음 |
| 실적 훼손 | 최신 공개 실적의 전년 동기 대비 매출 또는 영업이익 감소, 혹은 영업적자 전환 시 청산 | 동일 |

- 일목 조건은 전환선>기준선, 종가>현재 위치의 구름 상단, 현재 종가>26거래일 전 종가로 계산한다. 후행스팬 구현에 미래 가격을 사용하지 않는다.
- 매수 단계는 실제 체결 후 진행하며 같은 거래일에는 다음 매수 단계로 넘어가지 않는다.
- 원문 기반형의 하락 추가 매수 후 첫 MACD 골든크로스에서는 보유 수량의 1/3을 한 번 축소한다. 이후 3차 조건이 성립하면 예정된 6의 예산만 사용하며 매도한 예산을 다시 채우지 않는다. 이는 원문의 ‘일부 정리’를 정량화한 별도 가설이다.
- 실적 자료가 없거나 정정본을 아직 수집하지 못한 상태와 실적 훼손을 구분한다. 결측만으로 실적 훼손 청산을 생성하지 않고 추가 매수를 차단한다.

### 분할매도

일반 분할매도는 매도 시작 시 보유 수량을 기준으로 한다.

1. 일 RSI가 70을 상향 돌파하거나 장중 호가 익절 조건 충족: 누적 1/9 매도.
2. 일 MACD 데드크로스: 누적 3/9 매도.
3. 전환선의 기준선 하향 돌파와 종가의 구름 진입·하향 이탈: 잔량 매도.

더 강한 매도 조건이 먼저 발생하면 해당 누적 목표까지 진행한다. 일반 분할매도가 시작되면 추가 매수를 중단한다. 안전형 가격 손절과 두 모드의 실적 훼손 청산은 분할 익절보다 우선한다. 하락 추가 매수 후의 일회성 반등 축소는 위 일반 분할매도와 구분해 기록한다.

### 예산과 계좌 통제

- 운영자가 지정한 전용 운용 예산을 두 모드에 50:50으로 배분한다. **1억 원은 연구 기본값이며 실계좌 예산으로 자동 적용하지 않는다.**
- 모드별 최대 5종목. 안전형의 종목 예산은 모드 자산의 최대 10%, 원문 기반형은 최대 13.5%다.
- 안전형은 한 매매 사이클의 손절 예상 손실 합계가 모드 자산의 0.5%를 넘지 않도록 각 차수 수량을 제한한다. 추가 매수로 기존 물량의 손절을 낮추지 않는다.
- 두 모드 모두 최소 현금 32.5%를 유지한다. 계좌 장세별 최소 현금 기준이 더 엄격하면 그 기준을 적용한다.
- 동일 종목의 두 모드 보유분, 기존 전략 보유분, 미체결 예약을 모두 합산해 계좌 한도를 검사한다. 한도 부족 시 차수를 건너뛰거나 예산을 빌리지 않고 대기한다.
- 원문 기반형의 가격 손절 부재를 결측 손절가와 구분하는 명시적 정책으로 표현한다.
- 킬스위치는 신규 진입 차단이며 손실을 특정 비율에서 확정적으로 멈추는 보장이 아니다. 기존 청산 승인 규칙을 유지한다.

## 3. 구현 구성과 인터페이스

### 데이터와 실시간 피드

기존 OHLCV·DART·업종 스냅샷을 재사용하고 연간 실적·배당 이력의 시점별 조회를 보완한다. 발표일, 최초 수집 시각, 정정 공시, 적용 가능 시점을 보존한다.

현재 `maps/data/dart_financials.py`는 실제 관측 시점을 반영한다. 오늘 받은 자료를 과거에도 알고 있었다고 간주하지 않는다. 과거 근거가 없는 구간은 백테스트 불가로 표시하고 전진 검증으로 채운다. 단순 날짜별 DPS 값이 있다고 3개년 확정 배당 이력이 확보된 것으로 보지 않는다.

전 시장은 장 마감 후 선별하되 실시간 구독은 **보유 종목·미체결 종목 우선, 신규 후보 순**으로 배정한다. 구독 용량 부족 시 신규 후보를 줄이고 보유 종목 감시는 유지한다. 전 시장 자동 선별을 전 종목 실시간 동시 구독으로 해석하지 않는다.

기존 `maps/limit_up/feed.py`의 호가 정규화는 최우선 호가 중심이다. 다음을 추가한다.

- 매수·매도 총잔량, 거래소 시각, 수신 시각, 연결·누락 상태.
- 후보 선정 당시 목록과 실제 사용한 호가 이벤트의 저장·재생.
- 상한가 엔진과 공유하는 구독 관리. 별도 연결이 기존 구독을 침범하지 않도록 통합한다.

호가 익절은 **예상 매도 비용을 차감해도 수익인 상태에서 총매수잔량/총매도잔량≥3이 30초 지속**할 때 발생한다. 매도잔량 0, 역전 호가, 3초 초과 데이터 공백은 판단 불가이며 지속 시간을 초기화한다. 잔량을 실제 체결 매수세로 해석하지 않는다.

### 전략·분할매매 원장

현재 `maps/strategy/base.py`는 진입·청산 신호 중심이고 `maps/backtest/portfolio_replay.py`는 보유 중 추가 진입을 제외한다. 기존 전략의 계약을 유지하면서 후지모토 전략용 상태 전이 함수를 추가한다.

- 입력: 시점별 시장 근거, 모드 설정, 보유·체결 상태.
- 출력: 매수 단계, 매도 누적 목표, 주문 가격 상한, 판단·차단 사유.
- 백테스트와 운영은 같은 상태 전이 함수를 사용한다.

DB에는 다음을 영속화한다.

- 모드별 예산과 설정 버전.
- 종목별 매매 사이클, 차수, 실제 보유 수량, 매도 기준 수량.
- 주문 의도 연결, 체결 누계, 사용한 데이터와 판단 근거.

두 모드에 서로 다른 전략 ID를 부여한다. 동일 종목이라도 수량·손익·매도 가능 수량을 분리하며 기존 계좌 보유분은 자동 편입하지 않는다. 미래 세션의 구현 계획에서 테이블·타입·API의 구체 명칭과 마이그레이션 번호를 당시 코드에 맞춰 확정한다.

### 주문과 운영 화면

기존 `maps/execution/order_manager.py`의 계좌 잠금, 주문 의도, 체결 대사, 예약 노출 검사를 재사용한다. 새 원장을 검증하는 실행 소스를 추가하고 기존 워치리스트의 위험검사 예외를 상속하지 않는다.

- 매수는 신호일 종가를 상한으로 다음 거래일 지정가 제출한다. 가격 추격과 시장가 전환은 없다.
- 장중 호가 익절은 유효한 최우선 매수호가 기준 지정가다. 미체결은 체결로 간주하지 않는다.
- 일반 기술적 청산은 다음 거래일, 가격 손절은 유효한 장중 시세, 실적 훼손 청산은 정보 사용 가능 이후 최초 주문 가능 시점에 처리한다.
- 종목·계좌 단위로 상충하는 매수·매도 제출을 직렬화하고 청산을 우선한다.
- 부분 체결은 체결량만 반영한다. 취소 확인 전 예약을 해제하지 않으며 결과 불명 주문은 재전송하지 않는다.
- 재시작 시 브로커 대사 후 재개한다. 불일치가 남으면 해당 계좌 신규 매수를 차단한다.

기존 웹 대시보드에 모드 비교, 차수·예산·예약 현금, 판단 근거, 피드 품질, 차단 사유를 추가한다. API는 설정 조회·변경, 후보·사이클 조회, 검증 결과 조회, 실행 활성화·중단을 제공한다. 관리자 권한과 사용자 소유 범위를 적용한다. 모바일 전용 화면은 첫 버전에서 제외한다.

자동매도는 활성화 시 해당 전략이 새로 취득할 물량과 청산 규칙에 대한 명시적 승인을 기록한다. 기존 보유분 청산과 계좌 비상 일괄 청산은 별도 승인을 유지한다.

## 4. 검증과 수용 기준

### 개발 테스트

- RSI 경계값·상수 가격, 주봉 확정, 일목 이동, 공시 정정·지연·결측의 미래정보 누출 검사.
- 1→2→6 체결 진행, 하락 추가 매수, 반등 축소, 분할매도, 정수 수량 잔여 처리.
- 동일 종목을 두 모드가 보유한 상태의 손익 분리·초과 매도 방지.
- 부분 체결, 취소 경합, 주문 응답 단절, 중복 이벤트, 재시작 복구.
- 호가 30초 지속, 피드 지연·단절·재연결, 구독 용량 부족.
- DB 마이그레이션, 권한·소유권, 기존 전략과 상한가 엔진 회귀.

### 전략 검증

- 안전형, 원문 기반형, 동시 운영을 각각 보고하고 호가 규칙 유무도 비교한다.
- 수수료·거래세·슬리피지·미체결을 반영한다. 지정가 접촉만으로 전량 체결을 가정하지 않는다.
- 현금 공유·중복 종목·예약 주문을 반영한 포트폴리오 리플레이를 수행한다.
- 상승·하락·횡보 구간, WFA, 주변 파라미터, 비용 2배 조건을 검증한다.
- 68% 동반 하락, 거래정지·연속 하한가·전액 손실 시나리오를 검사한다. 손절과 킬스위치를 확정 손실 상한으로 표현하지 않는다.

승격에는 기존 MAPS 검증 게이트를 적용하고 두 모드 및 합산 계좌의 위험 검증 결과를 추가로 요구한다. 연구 기본값으로 안전형 MC MDD p95 기준은 15%, 원문 기반형은 25%, 합산은 설정된 계좌 MDD 한도를 사용한다. 이는 연구 통과 기준이며 실현 손실 보장이 아니다.

호가 기능은 기록된 이벤트로 재생 검증한 뒤 모의 운영한다. 데이터·거래 표본이 부족하면 ‘통과’ 대신 ‘검증 부족’으로 남기며 실거래 승격 조건을 완화하지 않는다. 두 모드가 각각 통과해도 합산 검증이 실패하면 동시 운영을 승격하지 않는다.

## 5. 단계별 구현과 현재 상태

1. **데이터·규칙:** 시점별 재무·배당·호가 근거, 정량 신호, 순수 상태 전이와 단위 테스트.
2. **연구:** 분할매매 원장과 이벤트 리플레이, 두 모드 및 합산 위험 검증.
3. **운영:** 주문 엔진 연결, 실시간 구독 공유, 복구·권한·대시보드.
4. **출시:** 연구 → 주문 없는 관찰 → 모의 검증 → 기존 승격 기준을 통과한 모드만 명시적으로 실거래 활성화.

복수 모듈·스키마 변경이므로 구현 시 ExecPlan을 유지한다. 조사 시점에 `.agent/PLANS.md`가 없었다. 구현 세션에서 존재 여부를 재확인하고, 계속 없다면 목적·진행 상황·결정 기록·검증·복구 절차를 포함한 계획 규약과 작업 ExecPlan을 먼저 작성한다. 관련 패키지 문서·색인·전략 가이드도 함께 갱신한다.

이 설계 저장 작업은 소스·설정·DB를 변경하지 않는다. 매매 규칙 구현, 백테스트, 수익성 검증, 실거래 활성화는 아직 수행하지 않았다. 가장 큰 선행 과제는 과거 시점의 재무·배당·호가 근거 확보이며, 확보되지 않은 구간의 성과를 임의 추정해 승격 근거로 사용할 수 없다.
