# 종목분석 가격의 전략매매 팝업 연결 설계

## 목적

종목분석 결과에 표시된 1·2·3차 매수가, 목표가, 손절가를 전략매매 팝업의
초깃값으로 그대로 사용한다. 분석 화면과 팝업이 서로 다른 AI 호출에서 가격을
만들지 않게 하며, 팝업 표면은 뒤 화면이 비치지 않는 불투명 배경으로 표시한다.

## 확인된 원인

1. 종목분석의 STEP 7 가격은 스트리밍 Markdown 문자열인 `_analysisText`에만 있고,
   주문에 사용할 수 있는 구조화 데이터로 보관되지 않는다.
2. `매매 설정`을 누르면 분석 결과를 재사용하지 않고 `/stock-analysis/trade-plan`을
   다시 호출한다. 따라서 화면에 표시된 가격과 팝업 가격이 같다는 보장이 없다.
3. 별도 호출의 JSON Schema에는 Bedrock이 지원하지 않는 `prefixItems`가 포함되어
   운영 요청이 `ValidationException`으로 실패한다.
4. 팝업 CSS가 정의되지 않은 `--bg` 변수를 사용해 배경색 선언이 무효가 되고,
   뒤의 종목분석 화면이 비친다.

## 결정

### 가격의 단일 원천

분석 시점에 구조화된 `trade_plan`을 한 번 생성하고, 이 객체를 가격의 단일 원천으로
사용한다. 객체에는 다음 값이 포함된다.

- `recommendation`: `BUY`, `WATCH`, `SELL`
- `entries`: 1·2·3차 매수가
- `target`: 목표가
- `stop`: 손절가
- `rationale`: 가격 근거
- `source`: `AI` 또는 `MANUAL_REQUIRED`

`recommendation`은 분석 의견을 표시하는 값이며 자동 입력 여부를 결정하지 않는다.
종목분석이 유효한 분할매수 계획을 제시했다면 `BUY`, `WATCH`, `SELL`과 관계없이
세 매수가·목표가·손절가를 같은 객체에 담는다. 주문은 팝업의 별도 검증과 사용자
확인 전에는 실행되지 않는다.

종목분석 화면에는 `trade_plan`으로 만든 표준 가격 요약을 표시한다. AI 종합분석
Markdown의 STEP 7도 이 값을 입력으로 받아 같은 숫자만 설명하게 한다. 독립적으로
다른 가격을 만들게 하지 않는다.

전략매매 팝업은 네트워크로 가격을 다시 생성하지 않는다. 분석 완료 이벤트에 포함된
동일한 `trade_plan`을 메모리에 보관하고, 팝업을 열 때 `entries`, `target`, `stop`을
입력란에 복사한다. 단일매매는 1차 매수가를 사용하고, 3분할매매는 세 매수가를 모두
사용한다.

### 분석 흐름

1. 기존 시세·기술·재무 데이터를 수집한다.
2. 수집한 데이터로 구조화 매매계획을 한 번 생성한다.
3. 서버가 KRX 호가 단위와 `target > entry1 > entry2 > entry3 > stop`을 검증한다.
4. 검증된 `trade_plan`을 AI 종합분석 입력에 포함한다.
5. SSE 완료 이벤트의 `data`와 함께 `trade_plan`을 내려보낸다.
6. 브라우저는 분석 가격 요약과 전략매매 팝업에 같은 객체를 사용한다.

기존 `/api/v1/stock-analysis/trade-plan`은 호환성을 위해 유지하되, 웹 팝업에서는
더 이상 호출하지 않는다. Bedrock 호환성을 위해 구조화 출력 스키마의 동일 타입
튜플은 `prefixItems` 대신 단일 `items`로 변환한다.

### 실패 및 안전 동작

- 구조화 계획 생성 실패, 누락, 비정상 숫자, 가격 순서 오류가 있으면 자동 입력하지
  않고 `MANUAL_REQUIRED`와 구체적인 안내를 표시한다.
- Markdown 문장에서 정규식으로 가격을 추출하지 않는다. 설명 형식 변화가 주문값을
  바꾸지 않게 한다.
- 자동 입력은 주문 실행이 아니다. 기존의 매매 방식 선택, 총 매수금액 입력,
  안전한도 계산, 서버 재검증, 사용자 최종 확인을 모두 유지한다.
- 팝업의 최초 자동 입력값은 분석 결과와 정확히 같아야 한다. 사용자가 이후 값을
  수정하는 것은 허용하되 출처를 수동 수정으로 바꾸고, 브라우저가 보내는 최종 값은
  기존 서버 검증을 다시 통과해야 한다.
- 실제 주문 마스터 스위치, 라이브 거래 게이트, 계좌 위험한도는 변경하지 않는다.

### 팝업 표시

`dialog.sa-trade-dialog`와 분석 워치리스트 딥다이브 표면은 존재하는 전역 변수
`--bg-base`를 사용한다. 배경은 불투명 색상이며, 반투명 처리는 `::backdrop`에만
적용한다. 작은 화면에서는 기존 2열 반응형 입력 배치를 유지한다.

## 테스트

1. Bedrock 요청 Schema에 `prefixItems`가 없고 숫자 배열 `items`가 있는지 확인한다.
2. 분석 완료 이벤트가 검증된 `trade_plan`을 포함하는지 확인한다.
3. 종합분석 프롬프트가 같은 `trade_plan` 가격을 입력받는지 확인한다.
4. 팝업이 `/trade-plan`을 다시 호출하지 않고 완료 이벤트의 값을 입력하는지 확인한다.
5. `BUY`, `WATCH`, `SELL` 모두 유효한 분석 가격이 있으면 자동 입력되는지 확인한다.
6. 단일매매는 1차 가격, 3분할매매는 세 가격을 사용하는지 확인한다.
7. 계획 실패·누락·가격 순서 오류 시 자동값이 비고 실행 버튼이 비활성인지 확인한다.
8. 팝업 표면이 `--bg-base`를 사용하고 `::backdrop`만 반투명인지 확인한다.
9. 기존 안전한도 계산·무장 API 및 전체 회귀 테스트를 실행한다.

## 범위 제외

- AI Markdown의 임의 문장을 파싱해 주문값으로 사용하는 기능
- 분석 결과를 DB에 장기 보관하는 새 테이블
- 전략매매 안전한도, 주문 조건, 실제 거래 모드 변경
- 모바일 APK 배포
