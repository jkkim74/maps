# KIS 주문 식별자 충돌 방지 설계

## 목적

KIS가 서로 다른 거래일에 같은 `ODNO`를 재사용해도 기존 `order_log` 행을 덮어쓰거나 새 주문의 감사 행을 누락하지 않게 한다. 브로커 동기화는 주문 식별자뿐 아니라 종목과 매매 방향도 일치할 때만 기존 행을 갱신해야 한다.

## 확인된 장애

2026-08-10 인바디(`041830`) 매수 주문의 KIS `ODNO=0000000755`가 2026-08-06 `051160` 매수 주문번호와 같았다. `order_log.order_id`의 전 기간 unique 제약으로 인바디 INSERT가 실패했고, broker sync가 `order_id`만 조회해 과거 행에 인바디 체결수량과 가격을 덮어썼다. 그 결과 실제 인바디 35주 보유와 DB 진입 기록이 연결되지 않아 자동 손절 감시가 누락됐다.

## 접근 비교

1. **내부 복합 ID(선택):** 기존 `order_id` 컬럼에 `kis:<계좌지문>:<KST주문일>:<ODNO>`를 저장한다. 스키마 변경 없이 기존 unique 제약을 올바른 범위의 안전장치로 유지한다.
2. **정규화 컬럼 추가:** raw ODNO, 계좌, 주문일 컬럼을 추가하고 복합 unique를 건다. 명시적이지만 마이그레이션과 모든 참조 변경이 필요하다.
3. **unique 제거:** raw ODNO 중복을 허용하고 조회 조건만 늘린다. 기존 `AnalysisPick.entry_order_id` 같은 단일 참조가 모호해져 채택하지 않는다.

## 설계

- KIS 주문 감사 ID는 `kis:<account_sha256_8>:<YYYYMMDD>:<raw_odho>` 형식이다. 계좌번호 원문은 저장하지 않는다.
- KIS 이외 브로커의 ID는 현재 동작을 유지한다.
- `OrderManager`는 KIS 주문 제출 결과를 내부 ID로 변환한 뒤 `order_log`에 기록하고 호출자에게도 내부 ID를 반환한다. 따라서 분석 픽 등 기존 DB 참조는 전역적으로 유일한 값을 유지한다.
- `KISAdapter.cancel_order()`는 내부 ID를 받으면 마지막 구성요소인 raw ODNO만 KIS API에 전달한다. 기존 raw ODNO 입력도 계속 지원한다.
- 당일 체결 sync는 같은 규칙으로 내부 ID를 계산해 조회한다. 배포 이전 레거시 행은 같은 KST 주문일, raw ODNO, ticker, side가 모두 일치할 때만 호환 조회한다.
- 찾은 행의 ticker 또는 side가 브로커 결과와 다르면 갱신을 거부하고 `sync_errors`를 증가시키며 오류 로그를 남긴다.
- MAPS 외부 주문은 같은 내부 ID로 `external_mts` 감사 행을 생성한다.

## 운영 복구

1. 운영 PostgreSQL 전체를 custom-format으로 백업하고 백업 파일 크기가 0보다 큰지 확인한다.
2. 단일 트랜잭션에서 기존 `051160` 행을 `expired`, `fill_qty=0`, `fill_price=NULL`로 원복한다.
3. 인바디 진입 행을 내부 복합 ID, `ath_breakout_v1`, BUY 35주, 주문가 71,600원, 체결가 69,200원, ATR14 `5638.281459`로 생성한다.
4. 실제 KIS 보유 35주와 DB 행을 대조하고 broker sync의 `skipped_sell_orders=0`, 계산 손절가 55,100원을 확인한다.

## 테스트와 완료 조건

- 서로 다른 KST 날짜의 동일 ODNO가 서로 다른 내부 ID가 되는 테스트가 먼저 실패해야 한다.
- 과거 동일 ODNO 행이 있어도 오늘 다른 ticker 결과가 과거 행을 변경하지 않는 회귀 테스트가 먼저 실패해야 한다.
- 내부 ID를 전달한 취소 요청이 raw ODNO로 전송되는 테스트가 먼저 실패해야 한다.
- 집중 테스트와 전체 테스트가 통과해야 한다.
- 운영 배포 전 DB 백업, 마이그레이션 상태, Git 상태를 확인한다.
- 배포 후 서비스 active, health 200, 복구된 주문 행, broker sync와 자동 손절 연결을 확인한다.
