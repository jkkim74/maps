# KIS KOSDAQ 지수 조회 간격 수정 설계

## 배경

상한가 V1 엔진을 운영 KIS 모의투자 계정에서 `recommend_only`로 기동했을 때
`get_kosdaq_index()`가 빈 응답을 받아 control loop가 반복 실패했다. 운영 호출을 한 차례
검증한 결과, `FID_INPUT_HOUR_1`에 공식 계약값인 `"60"`을 보내면 정상 응답 100행과
KOSDAQ 현재값이 반환됐다.

현재 구현은 이 필드에 KST 현재시각을 `HHMMSS` 형식으로 넣는다. 그러나 KIS의
`inquire-index-timeprice` 계약에서 이 필드는 조회 간격이며 `60`, `300`, `600` 같은 값을
받는다. 엔진과 서비스는 안전하게 다시 꺼졌고, 검증 시도 중 주문과 상한가 DB 기록은
생성되지 않았다.

## 목표

- KOSDAQ 지수 조회가 KIS 공식 계약에 맞는 1분 간격 파라미터를 사용한다.
- 지수 조회는 KRX 정규장(09:00~15:30)에만 수행한다.
- 회귀 테스트가 정확한 `FID_INPUT_HOUR_1` 값을 검증한다.
- 수정 후 운영 `recommend_only` 엔진이 반복 오류 없이 기동하고 후보 감시를 수행한다.
- 검증 중 상한가 실주문은 한 건도 발생하지 않는다.

## 비목표

- 다른 지수 조회 API로 교체하지 않는다.
- 빈 응답에 대한 폴백이나 캐시를 새로 만들지 않는다.
- `automatic` 모드로 전환하지 않는다.
- 상한가 전략의 신호·사이징·위험 한도를 변경하지 않는다.

## 설계

`KISAdapter.get_kosdaq_index()`가 보내는 `FID_INPUT_HOUR_1`을 KST 현재시각 대신 문자열
`"60"`으로 고정한다. 모듈 상단에 `_INDEX_TIME_INTERVAL_SECONDS = "60"`으로 선언해 이 값이
KIS 프로토콜 상수임을 드러낸다. 운영 설정으로 바꿀 이유가 없는 공식 1분 간격 계약이므로
환경변수로 노출하지 않는다.

기존 `test_websocket_approval_and_kosdaq_index_use_official_contract`에 요청 파라미터
`FID_INPUT_HOUR_1 == "60"` 단언을 추가한다. 구현 전 이 테스트가 현재시각 값 때문에
실패하는 것을 확인하고, 한 줄 수정 후 통과시키는 TDD 순서를 따른다.

### 지수 조회 시간 게이트

전체 엔진 창은 익일 08:59:30 청산과 15:28 이후 강제청산을 처리하기 위해
08:50~15:40으로 유지한다. 하지만 KOSDAQ 지수는 신규 진입 중단 판단에만 필요하므로
별도 순수 함수 `index_guard_active_at()`로 09:00~15:30에만 조회한다. 이 경계를
control loop의 지수 호출 조건에 적용하고 08:59:59, 09:00:00, 15:30:00, 15:30:01을
테스트한다.

### KIS 응답 mock 범위

현재 테스트 응답은 운영과 동일하게 `output` 리스트 안의 행에
`bstp_nmix_prpr` 현재값을 둔다. 파서는 최신 첫 행만 사용하므로 운영에서 관측한 100행을
그대로 복제하거나 행 수를 계약으로 고정하지 않는다. 정확한 요청 파라미터와 실제로 읽는
응답 필드만 회귀 테스트가 책임진다.

## 오류 처리

기존 동작을 유지한다. KIS가 성공 응답에도 지수 행을 주지 않으면
`BrokerAdapterError("KIS KOSDAQ index response was empty")`를 발생시킨다. 잘못된 요청을
폴백으로 감추지 않아 운영 로그에서 계약 위반이나 외부 장애를 즉시 확인할 수 있게 한다.

## 검증 및 배포

1. 수정된 단일 테스트가 구현 전 예상한 이유로 실패하는지 확인한다.
2. 지수 조회 시간 경계 테스트도 구현 전 실패하는지 확인한다.
3. 프로토콜 상수와 정규장 게이트를 최소 구현하고 관련 테스트를 통과시킨다.
4. 상한가 집중 테스트와 전체 테스트, `compileall`, `git diff --check`를 실행한다.
5. 수정 커밋을 `master`에 push하고 운영 서버에 배포한다.
6. 운영 `.env`를 권한 보존 백업한 뒤 `MAPS_LIMIT_UP_ENABLED=true`,
   `MAPS_LIMIT_UP_MODE=recommend_only`로 기동한다.
7. 서비스와 `/health`, 인증된 `/api/v1/limit-up/status`, 운영 로그를 확인한다.
8. KOSDAQ 빈 응답·반복 control-loop 오류가 없고 `limit_up_v1` 주문이 0건인지 확인한다.
9. 오류가 재발하면 즉시 백업 설정으로 롤백하고 엔진을 OFF로 유지한다.

## 완료 기준

- KIS 요청이 `FID_INPUT_HOUR_1="60"`을 사용한다.
- KOSDAQ 지수 REST 호출이 09:00~15:30 밖에서는 발생하지 않는다.
- 모든 코드 검증이 통과한다.
- 운영 엔진 상태가 `recommend_only`이며 `manual_lock=false`, `unknown_positions=[]`다.
- 관찰 구간에 KOSDAQ 지수 조회 오류와 상한가 실주문이 없다.
