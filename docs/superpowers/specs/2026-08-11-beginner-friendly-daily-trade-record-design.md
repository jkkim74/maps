# 초보자용 일일 매매 기록 원고 설계

## 1. 목적

SCR-20 `매매 기록`은 저녁 배치가 생성한 네이버 블로그용 평문 원고를 날짜별로 보여준다.
현재 원고는 시장 국면, 변동성, Breadth, 전략 ID와 같은 전문 정보를 설명 없이 노출해
주식 초보자가 오늘 무엇을 했고 왜 그렇게 했는지 이해하기 어렵다.

이번 변경의 목적은 원고 자체를 다음 순서로 읽히게 만드는 것이다.

1. 오늘 무슨 일이 있었는지 쉽게 이해한다.
2. 시스템이 왜 매수·매도·대기를 선택했는지 이해한다.
3. 원래 용어와 상세 숫자가 필요한 독자는 같은 원고의 상세 기록에서 확인한다.

## 2. 범위

### 포함

- `.claude/commands/blog.md`의 원고 구성과 작성 지침을 초보자 중심으로 개편
- `docs/blog_style_naver.md`에 초보자용 표현 규칙과 예시 추가
- 기존 원고 검사기에 설명 없는 핵심 전문용어를 찾는 가독성 검사 추가
- 생성 프롬프트, 용어 검사, 기존 네이버 형식에 대한 회귀 테스트 추가

### 제외

- `DailyDigest` 스키마와 수치 산출 방식 변경
- DB 또는 새 매매일지 입력 모델 추가
- SCR-17 거래 리뷰의 손익 계산과 거래 페어링 수정
- SCR-20 화면 레이아웃 변경
- AI 투자 조언, 거래 평가, 감정 기록, 사용자 입력 기능
- 네이버 자동 발행

## 3. 선택한 접근법

한 원고를 `쉬운 본문`과 `상세 기록`으로 나눈다. 쉬운 본문은 초보자가 이해해야 하는
행동과 이유만 설명한다. 상세 기록은 기존 시장 지표, 전략 ID, 후보 점수와 주문 수치를
보존한다.

현재 8개 전문 섹션을 그대로 쉽게 번역하면 정보량이 여전히 많고, 핵심만 남기면 감사와
검증에 필요한 값이 사라진다. 두 층을 한 원고에 두면 초보자는 앞부분만 읽을 수 있고,
운영자는 뒷부분에서 원래 데이터를 확인할 수 있다.

## 4. 원고 구조

제목과 태그는 기존처럼 네이버 에디터의 별도 입력란을 위한 평문으로 분리한다. 본문은
아래 7개 섹션을 이 순서로 작성한다.

### 1. 오늘의 매매 한눈에

- 세 문장 이내
- 매수·매도 체결 건수, 신규매수 중단 여부, 확인이 필요한 데이터만 요약
- 숫자를 반복하거나 뒤에서 다시 요약하지 않음

예시:

> 오늘은 매수 1건이 전량 체결됐고 매도는 없었습니다. 상승과 하락 신호가 섞인
> 시장(MIXED)이어서 신규매수 한도는 평소보다 낮았습니다. 확인이 필요한 주문 기록은
> 없습니다.

### 2. 오늘 시장은 어땠나요?

- `regime`, `raw_regime`, `weekly_trend`, `vol_regime`, `breadth_pct`,
  `entry_limit_ratio`를 쉬운 문장으로 연결
- `floor_applied`와 한국시장 약세 가드처럼 실제 매매 한도에 영향을 준 보정은 이유를 설명
- `measured: false`인 팩터는 수치로 해석하지 않고 미측정이라고 표시
- 원래 용어는 첫 등장에 괄호로 함께 표시

### 3. 시스템은 왜 이렇게 움직였나요?

- 오늘 실제 행동에 영향을 준 활성 전략과 차단 이유를 우선 설명
- 활성·비활성 전략을 본문에서 전부 나열하지 않음
- 체결이 없으면 시장과 전략 차단 이유를 연결해 설명
- 전략 ID는 쉬운 전략 설명 뒤 괄호로 한 번만 표시하고 전체 목록은 상세 기록으로 이동

### 4. 실제 매수·매도 기록

각 체결을 다음 순서로 쓴다.

1. 무엇을 했는가: 종목명, 매수·매도, 체결수량, 체결가격
2. 왜 했는가: `entry_rationale` 또는 `exit_reason`
3. 얼마나 체결됐는가: 전량·부분·미체결 상태
4. 무엇을 확인해야 하는가: 불리한 체결, 사유 누락, 데이터 불일치가 있을 때만 표시

손익 결과만으로 좋은 거래 또는 나쁜 거래라고 평가하지 않는다. 계획한 규칙의 실행 여부만
설명한다.

### 5. 내일 예정된 행동

- `tomorrow_orders.items`를 매수 예정, 조건 대기, 주문 제외로 풀어 설명
- `skipped`, `skip_reason`, `data_stale`, `live_eligible`을 행동 중심 문장으로 표현
- 모의 단계 전략을 실제 주문 예정처럼 쓰지 않음

### 6. 상세 기록

기존 전문 정보의 감사 영역이다.

- 시장 원시·적용 국면, 주간 추세, 변동성, 시장폭, 신규매수 한도
- 강세 업종 점수와 관측 전용 여부
- 전략 ID, 활성 상태, 단계, 차단 이유
- 후보 종목 점수와 근거, 제외 사유
- 주문가, 체결가, 수량, 체결 상태, 청산 사유

쉬운 본문에서 설명한 원래 용어와 코드를 그대로 보존한다. 상세 기록에 새로운 해석이나
숫자를 추가하지 않는다.

### 7. 투자 유의사항

기존 문구를 유지한다.

> 이 기록은 KIS 모의투자 계좌의 운용 결과이며 실제 자금 운용이 아닙니다.
> 특정 종목의 매수·매도를 권유하지 않습니다.
> 투자 판단과 결과의 책임은 투자자 본인에게 있습니다.

## 5. 쉬운 표현 규칙

### 기본 형식

핵심 전문용어의 첫 등장은 `쉬운 설명(원래 용어)` 형식으로 쓴다. 이후 같은 원고에서
반복될 때는 쉬운 설명만 쓸 수 있다. 값과 코드를 숨기지 않고 독자가 뜻과 원래 용어를
함께 익히게 한다.

### 필수 용어 사전

| 원래 용어 | 첫 등장 표현 |
|---|---|
| `STRONG` | 상승 흐름이 뚜렷한 시장(STRONG) |
| `MIXED` | 상승과 하락 신호가 섞인 시장(MIXED) |
| `WEAK` | 하락 압력이 큰 시장(WEAK) |
| `LOW` 변동성 | 가격 움직임이 평소보다 작은 상태(LOW 변동성) |
| `NORMAL` 변동성 | 가격 움직임이 평소 수준인 상태(NORMAL 변동성) |
| `HIGH` 변동성 | 가격 움직임이 평소보다 큰 상태(HIGH 변동성) |
| `Breadth` | 오르는 종목의 비율(Breadth) |
| `entry limit` | 오늘 허용된 최대 신규매수 비율(entry limit) |
| `filled` | 주문 수량이 모두 거래된 상태(filled) |
| `partially filled` | 주문 수량 중 일부만 거래된 상태(partially filled) |
| `stop loss` | 손실 제한 가격에 도달한 매도(stop loss) |
| `take profit` | 목표 가격에 도달한 매도(take profit) |

전략 ID는 고정 번역표를 새로 만들지 않는다. 다이제스트의 전략 정보와 기존 전략 가이드를
근거로 한 문장 설명을 먼저 쓰고 원래 ID를 괄호에 둔다. 근거가 없으면 ID의 의미를
추측하지 않고 `전략 이름(ID)`까지만 쓴다.

### 숫자 표현

- 수치만 나열하지 않고 그 수치가 오늘 행동에 준 의미를 한 번 설명
- 다이제스트에 없는 숫자는 생성하거나 추정하지 않음
- 다이제스트의 두 값으로 계산한 차이·비율은 기존 허용 범위를 유지
- 수익률이나 손익을 성과 평가 또는 투자 추천으로 확대하지 않음

### 결측·오류 표현

- `measured: false`: `현재 연결된 데이터가 없어 확인하지 못했습니다.`
- `null`: `기록 없음`으로 표시하고 값을 만들지 않음
- 섹션 오류: 해당 섹션만 `수집 실패`로 표시하고 정상 섹션은 계속 작성
- AI 분석 실패: 규칙 기반 데이터만 설명
- `exit_reason` 누락: `매도 이유가 기록되지 않았습니다.`
- 오래된 주문 데이터: 실제 예정 주문처럼 쓰지 않고 먼저 경고

## 6. 데이터 흐름과 변경 지점

1. `maps.ops.daily_digest.build_daily_digest`가 기존과 동일하게 JSON을 만든다.
2. `scripts/run_blog_cron.sh`가 기존과 동일하게 `/blog` 명령을 실행한다.
3. `.claude/commands/blog.md`가 7개 섹션과 쉬운 표현 규칙에 따라 평문 원고를 생성한다.
4. `scripts/verify_blog_numbers.py`가 기존과 동일하게 원고 숫자를 다이제스트와 대조한다.
5. `scripts/check_naver_format.py`가 붙여넣기·문체 검사에 가독성 검사를 더해 결과를 보고한다.
6. 사람이 SCR-20에서 원고를 검토한 뒤 네이버에 복사한다.

새 서비스, 새 DB 테이블, 새 외부 의존성은 추가하지 않는다. 기존 배치가 이미 포맷 검사기를
호출하므로 `run_blog_cron.sh`에 별도 실행 단계를 만들지 않는다.

## 7. 가독성 검사기 설계

기존 검사기에 `readability` 범주를 추가한다. 기본 실행은 `paste`, `style`,
`readability` 세 범주를 검사하고 `--paste-only`는 기존처럼 붙여넣기 규칙만 검사한다.

가독성 검사는 `6. 상세 기록` 앞의 쉬운 본문만 대상으로 한다. 상세 기록은 원시 값과
식별자를 보존하는 감사 영역이므로 검사 대상에서 제외한다. 쉬운 본문에 필수 용어 사전의
원래 용어가 등장할 때 다음을 확인한다.

- 첫 등장에 승인된 `쉬운 설명(원래 용어)` 문구를 사용함
- 설명 없이 원래 용어만 노출되면 경고
- 쉬운 본문에 해당 원래 용어가 없으면 위반으로 보지 않음

검사는 생성 배치를 실패시키지 않고 기존과 같이 경고를 남긴다. 자연어 품질을 정규식으로
완벽히 판정하려 하지 않는다. 섹션 구조와 핵심 용어의 첫 설명만 기계적으로 보장한다.

## 8. 테스트

### 프롬프트 계약

- 7개 섹션 제목과 순서가 `.claude/commands/blog.md`에 존재
- 쉬운 본문과 상세 기록의 역할이 명시됨
- 필수 용어 사전의 표현이 프롬프트에 존재
- 미측정·누락·수집 실패·AI 실패에 대한 추측 금지가 유지됨
- 투자 추천 금지와 모의투자 면책이 유지됨

### 검사기 회귀

- `상승과 하락 신호가 섞인 시장(MIXED)`는 통과
- 설명 없이 `MIXED`를 먼저 쓰면 가독성 경고
- 상세 기록에서 감사값 `MIXED`를 쓰는 것은 가독성 검사 대상이 아님
- Breadth, entry limit, 변동성, 체결·청산 상태에도 같은 원칙 적용
- 기존 붙여넣기·이모지·em dash·상투구 검사 결과가 변하지 않음
- 전략 가이드 검사는 기존 `paste`, `style` 범위만 유지해 이번 원고 전용 사전과 분리

### 통합 확인

- 거래 없음
- 전량 체결
- 부분체결
- 손실 제한 매도
- 목표 가격 매도
- 데이터 미측정과 섹션 수집 실패

각 대표 다이제스트에서 생성 규칙이 요구하는 문장 예시를 테스트 계약으로 확인한다. 테스트는
외부 AI를 호출하지 않고 프롬프트와 검사기의 결정적 규칙만 검증한다. 실제 생성 원고 한 편은
수동으로 읽어 쉬운 본문, 상세 기록, 숫자 대조, 네이버 붙여넣기 형식을 최종 확인한다.

## 9. 완료 조건

- 원고 앞부분만 읽어 오늘 시장, 시스템 행동, 실제 체결, 내일 계획을 이해할 수 있음
- 핵심 전문용어가 첫 등장에 `쉬운 설명(원래 용어)`로 표시됨
- 기존 전문 수치와 식별자가 상세 기록에 보존됨
- 다이제스트 밖의 사실과 숫자를 만들지 않음
- 기존 숫자 검증과 네이버 평문 규약을 계속 준수함
- 기존 배치·API·SCR-20 화면 동작을 변경하지 않음
