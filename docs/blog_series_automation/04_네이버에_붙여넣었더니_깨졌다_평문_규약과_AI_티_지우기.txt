스마트에디터는 마크다운을 렌더링하지 않습니다.

구분선만 문제였습니다.

본문 30자가 안 접힌다고 구분선 30자가 안 접히는 게 아니었습니다.

20자로 내렸습니다.
이미 써 둔 시리즈 원고 20편(구분선 230개)도 같은 날 전부 20자로 바꿨습니다.
본보기가 규약을 어기면 규약이 무의미해지니까요. 산문은 한 글자도 안 건드렸습니다.

4. 검사 스크립트
────────────────────

규약을 문서로만 두면 안 지켜집니다. 검사기를 만들었습니다.
배치가 원고 생성 직후에 돌리고, 테스트도 같은 함수를 부릅니다.

▶ 파일: scripts/check_naver_format.py (핵심부)

  # 이모지. 붙여넣기는 되지만 글이 AI 생성물로 읽힌다.
  # 구분선(U+2500)·화살표(▶)·원문자(①)는 기하 도형이라 걸리지 않는다.
  _EMOJI = (
      "[\U0001F300-\U0001FAFF"   # 그림문자·이모티콘·기호
      "\U0001F1E6-\U0001F1FF"    # 국기
      "\\u2600-\\u27BF"        # 기타 기호·딩벳 (경고 표시, 체크 표시, 별 등)
      "\\u2B00-\\u2BFF"        # 화살표·별
      "\\uFE0F]"               # 이모지 변형 선택자
  )

  # 블로그 상투구. 정보가 0인 표현만 고른다. 정상적인 한국어를 막으면
  # 글쓴이가 규칙을 무시하게 되므로 목록을 짧게 유지한다.
  _CLICHES = (
      # 3편 문체 규칙 3번의 여덟 표현. 이 글에 그대로 적으면
      # 이 검사기가 이 글을 잡기 때문에 여기서는 생략한다.
  )

  # (갈래, 이름, 패턴). 줄 단위로 검사한다.
  _RULES = (
      (PASTE, "제목 기호(#)",   re.compile(r"^#{1,6}\s")),
      (PASTE, "굵게(별표 2개)", re.compile(r"\*{2}")),
      (PASTE, "백틱",           re.compile("\\u0060")),
      (PASTE, "표(|)",          re.compile(r"^\s*\|")),
      (PASTE, "구분선(---)",    re.compile(r"^-{3,}\s*$")),
      (PASTE, "인용(>)",        re.compile(r"^\s*>\s")),
      (PASTE, "링크",           re.compile(r"\]\(")),
      (STYLE, "이모지",         re.compile(_EMOJI)),
      (STYLE, "em dash",        re.compile("\\u2014")),
      (STYLE, "상투구",         re.compile("|".join(re.escape(c) for c in _CLICHES))),
  )

  (원본 소스는 이모지 범위와 em dash를 문자 그대로 적어 두었습니다.
   이 글에서는 검사기에 걸리지 않도록 유니코드 이스케이프로 바꿨습니다. 동작은 같습니다.)


  def find_violations(text, categories=(PASTE, STYLE, READABILITY)):
      """(줄번호, 갈래, 규칙명, 줄내용) 목록. 규약을 지키면 빈 리스트."""
      out = []
      for lineno, line in enumerate(text.splitlines(), 1):
          for category, name, pattern in _RULES:
              if category in categories and pattern.search(line):
                  out.append((lineno, category, name, line.strip()))
      if READABILITY in categories:
          out.extend(_find_readability_violations(text))
      return out

검사는 세 갈래입니다.

  paste        붙여넣으면 깨지는 것. 마크다운 잔재.
  style        AI가 쓴 티가 나는 표기. 이모지, em dash, 상투구.
  readability  쉬운 본문에서 설명 없이 먼저 나온 전문용어 (다음 절).

종료 코드는 항상 0입니다. 발행은 사람이 하니까 배치를 죽이지 않고 목록만 남깁니다.

  python scripts/check_naver_format.py blog/2026-09-04.txt
  [포맷] 2026-09-04.txt: 붙여넣기 위반 0건, 문체 위반 0건, 가독성 위반 6건

em dash 이야기를 하나 하면, 이 문자는 제가 본 AI 글의 지문 중 가장 흔합니다.
프롬프트로 금지해도 가끔 새어 나옵니다. 검사기가 있어야 잡힙니다.
그리고 이 검사기를 만들면서 알았는데, 제 코드 주석에도 em dash가 수십 개 있었습니다.
AI랑 같이 코딩하면 그렇게 됩니다.

한 원고를 두 층으로 나눴습니다.

  1. 오늘의 매매 한눈에          ┐
  2. 오늘 시장은 어땠나요?        │
  3. 시스템은 왜 이렇게 움직였나요? │ 쉬운 본문 (초보자용)
  4. 실제 매수·매도 기록          │
  5. 내일 예정된 행동             ┘
  6. 상세 기록                    → 원시 값과 식별자 보존 (감사용)
  7. 투자 유의사항

쉬운 본문에서 전문용어를 처음 쓸 때는 반드시 "쉬운 설명(원래 용어)" 형식으로 씁니다.
용어 사전을 프롬프트와 규약 문서에 똑같이 넣었습니다.

  상승 흐름이 뚜렷한 시장(STRONG)
  상승과 하락 신호가 섞인 시장(MIXED)
  하락 압력이 큰 시장(WEAK)
  가격 움직임이 평소보다 작은 상태(LOW 변동성)
  가격 움직임이 평소 수준인 상태(NORMAL 변동성)
  가격 움직임이 평소보다 큰 상태(HIGH 변동성)
  오르는 종목의 비율(Breadth)
  오늘 허용된 최대 신규매수 비율(entry limit)
  주문 수량이 모두 거래된 상태(filled)
  주문 수량 중 일부만 거래된 상태(partially filled)
  손실 제한 가격에 도달한 매도(stop loss)
  목표 가격에 도달한 매도(take profit)

  좋음: 상승과 하락 신호가 섞인 시장(MIXED)이었습니다.
  나쁨: 오늘은 MIXED 국면이다.

같은 원고에서 두 번째부터는 쉬운 설명만 써도 됩니다.
6번 상세 기록에서는 원래 용어를 그대로 씁니다.

전략 ID는 고정 번역표를 만들지 않았습니다.
다이제스트와 전략 가이드에 설명 근거가 있으면 한 문장 설명 뒤에 괄호로 ID를 붙이고,
근거가 없으면 의미를 추측하지 말고 "전략 이름(ID)"까지만 쓰라고 했습니다.

바뀐 뒤 9월 1일자 원고의 2번 섹션입니다.

  시장 상태는 상승과 하락 신호가 섞인 시장(MIXED)이었습니다.
  원시 판정도 MIXED로 같았고, 한국 시장 흐름을 반영해
  최소 등급을 올리는 보정(floor)이나 해외 신호보다 한국이
  약할 때 등급을 내리는 보정(korea weak guard)은
  둘 다 적용되지 않았습니다.

  주간 추세는 fail이었습니다.
  가격 움직임은 평소보다 큰 상태(HIGH 변동성)였습니다.

  여기서 결정적인 것은 주간 추세 fail입니다.
  오늘 허용된 최대 신규매수 비율은 0%로 내려갔습니다.
  시장이 완전히 무너져서가 아니라, 주간 흐름이
  기준선을 넘지 못했기 때문에 신규 진입 자체를
  잠근 것입니다.

같은 데이터인데 읽힙니다.


────────────────────
6. 가독성 검사와 그 한계
────────────────────

용어 사전이 지켜지는지 검사기에 readability 갈래를 추가했습니다.
쉬운 본문(6번 상세 기록 앞까지)에서 원래 용어가 쉬운 설명보다 먼저 나오면 잡습니다.

▶ 파일: scripts/check_naver_format.py (발췌)

  _DETAIL_HEADING = re.compile(r"(?m)^\s*6\.\s*상세 기록\s*$")
  _READABILITY_TERMS = (
      ("MIXED", re.compile(r"(?<![A-Za-z0-9_])MIXED(?![A-Za-z0-9_])"),
       "상승과 하락 신호가 섞인 시장(MIXED)"),
      ("entry limit", re.compile(r"(?<![A-Za-z0-9_])entry\s+limit(?![A-Za-z0-9_])"),
       "오늘 허용된 최대 신규매수 비율(entry limit)"),
      ...
  )

  def _find_readability_violations(text):
      detail = _DETAIL_HEADING.search(text)
      easy_body = text[:detail.start()] if detail else text
      out = []
      for label, raw_pattern, approved in _READABILITY_TERMS:
          raw = raw_pattern.search(easy_body)
          approved_at = easy_body.find(approved)
          if raw is None or (approved_at >= 0 and approved_at <= raw.start()):
              continue
          lineno = easy_body.count("\n", 0, raw.start()) + 1
          out.append((lineno, READABILITY, f"쉬운 설명 누락({label})", ...))
      return out

9월 4일 출력에 가독성 위반이 6건 있었습니다. 하나를 보면 이렇습니다.

  67행 쉬운 설명 누락(STRONG): 흐름이 뚜렷한 시장(STRONG)에서만 도는 전략입니다.

원고를 열어 보니 "상승" 이 앞줄 끝에 있고 "흐름이 뚜렷한 시장(STRONG)" 이 다음 줄이었습니다.
한 줄 30자 규칙 때문에 줄이 바뀌면서 검사기가 찾는 문구가 두 줄로 쪼개진 겁니다.
AI는 규약을 지켰고 검사기가 못 알아본 겁니다.

이건 아직 안 고쳤습니다. 6건 전부 같은 원인이라 눈으로 넘기면 5초입니다.
검사기를 고치는 게 맞지만, 한 줄로 합쳐서 비교하면 진짜 위반도 놓칠 수 있어서 보류 중입니다.
검사기는 보조 수단이지 판정자가 아닙니다.

7. 규약을 테스트로 고정한다
────────────────────

규약이 시간이 지나며 흐트러지는 걸 막으려고 세 가지를 테스트로 묶었습니다.

  · 본보기 원고(전략 가이드 9편)가 전부 검사를 통과하는지
  · 검사기가 깨진 형태 하나하나를 실제로 잡는지 (통과만 확인하면 빈 검사기도 초록)
  · 프롬프트와 규약 문서의 용어 사전이 글자 하나 안 틀리고 같은지

▶ 파일: tests/test_naver_blog_format.py (발췌)

  @pytest.mark.parametrize("guide", sorted(_GUIDE_DIR.glob("*.txt")), ids=lambda p: p.name)
  def test_strategy_guides_follow_the_convention(guide):
      violations = find_violations(guide.read_text(encoding="utf-8"), (PASTE, STYLE))
      assert not violations, "\n".join(
          f"{guide.name}:{lineno} {name} - {line[:60]}"
          for lineno, _cat, name, line in violations
      )
