안녕하세요 :)

이 블로그에는 매 거래일 저녁마다 "오늘의 매매 기록" 글이 올라갑니다.

글 한 편에 1만 2천 자쯤 됩니다.

이 글을 제가 쓰지 않습니다.
서버에서 저녁 6시 30분에 배치가 돌고, 5분 뒤에 원고가 파일로 떨어집니다.
저는 그걸 복사해서 붙여넣기만 합니다.

7월 27일에 첫 버전을 만들었고 오늘(9월 초)까지 29편이 나왔습니다.
그 사이에 삽질도 많이 했고 구조도 두 번 갈아엎었습니다.
이 시리즈 5편에 그 과정을 처음부터 순서대로 남깁니다.
프롬프트와 소스를 그대로 붙일 테니 따라 만드실 수 있을 겁니다.

AI가 글을 쓰는 것 자체는 어렵지 않습니다.
AI가 쓴 투자 글의 숫자를 믿을 수 있게 만드는 게 어렵습니다.


────────────────────
1. 왜 자동화했나
────────────────────

저는 국내 주식 자동매매 시스템(MAPS)을 혼자 만들어 돌리고 있습니다.
KIS 모의투자 계좌로 매일 아침 주문이 나가고 오후에 청산이 됩니다.

문제는 기록이었습니다.
시스템이 왜 그 종목을 샀는지는 DB 여기저기에 흩어져 있습니다.
시장 국면은 이 테이블, 후보 점수는 저 테이블, 주문은 또 다른 테이블.
장이 끝나고 그걸 다 모아서 글로 정리하는 데 한 시간이 걸렸습니다.

사흘 하고 그만뒀습니다.

그런데 매매 기록은 저한테 꼭 필요했습니다.
한 달 뒤에 "왜 그때 그걸 샀지?"를 되짚으려면 그날의 판단 근거가 남아 있어야 합니다.
블로그는 그 기록을 남기는 가장 게으른 방법이었습니다.
남이 읽는다는 압박이 있어야 매일 남기게 되니까요.

그래서 조건이 이랬습니다.

  · 매일 저녁, 사람 손 없이 원고가 나와야 한다
  · 글에 있는 숫자는 전부 DB에서 온 것이어야 한다
  · AI가 없는 분석을 지어내면 안 된다
  · 네이버 블로그에 그대로 붙여넣을 수 있어야 한다
  · AI가 쓴 티가 나면 안 된다


────────────────────
2. 첫 설계에서 버린 것
────────────────────

처음 떠올린 구조는 단순했습니다.
AI 에이전트한테 DB 접속 권한을 주고 "오늘 매매 기록 써줘" 하면 되지 않나.

하루 만에 버렸습니다.

AI가 DB를 직접 조회하면 무슨 쿼리를 날릴지 제가 통제할 수 없습니다.
같은 질문에 오늘은 이 테이블을 보고 내일은 저 테이블을 봅니다.
숫자가 틀려도 어디서 틀렸는지 추적이 안 됩니다.
가장 무서운 건, 데이터가 없을 때 AI가 그럴듯한 값을 만들어 채운다는 겁니다.

투자 글에서 이건 치명적입니다.

그래서 구조를 두 단계로 쪼갰습니다.

  1단계  파이썬 코드가 DB에서 하루치 JSON을 만든다
         (숫자와 사유의 유일한 출처)
  2단계  AI가 그 JSON 파일 하나만 읽고 글을 쓴다
         (DB 접속 권한 없음, 셸 실행 권한 없음)

객관성을 프롬프트로 부탁하지 않고 구조로 강제한 겁니다.
JSON에 없는 숫자는 글에 나올 수가 없습니다. 볼 수 있는 게 그 파일뿐이니까요.

이 원칙 하나가 이후 모든 결정의 기준이 됐습니다.
2편에서 1단계를, 3편에서 2단계를 소스와 함께 다룹니다.


────────────────────
3. 환경
────────────────────

따라 만드실 분을 위해 제 환경을 그대로 적습니다.

  서버        : AWS Lightsail (서울 리전), Ubuntu
  앱          : Python 3 + FastAPI, PostgreSQL
  AI 도구     : Claude Code CLI (claude 명령)
  글 모델     : claude-opus-5
  스케줄러    : 리눅스 cron (/etc/cron.d)
  발행 대상   : 네이버 블로그 스마트에디터 (복사해서 붙여넣기)

Claude Code CLI는 Node로 설치합니다. 서버의 Node는 v20입니다.

  npm i -g @anthropic-ai/claude-code
  claude --version
  → 2.1.197 (Claude Code)

인증은 API 키가 아니라 구독 계정 OAuth 로그인을 씁니다.
서버에서 ubuntu 사용자로 한 번 로그인해 두면 ~/.claude/ 아래에 인증이 저장됩니다.

  claude          (첫 실행에서 브라우저 로그인 안내가 나옵니다)

여기서 하나 중요한 게 있습니다.
cron은 반드시 그 로그인한 사용자(ubuntu)로 돌려야 합니다.
root로 돌리면 인증 파일을 못 찾아서 조용히 실패합니다.
저는 이걸로 첫날 저녁 한 번 날렸습니다.

API 키 방식을 쓰고 싶으면 /etc/maps/anthropic.env 에 키를 두고
래퍼 스크립트가 있을 때만 읽게 해 뒀습니다. 5편에서 그 코드가 나옵니다.

  16:40  OHLCV 수집 (앱 스케줄러)
  16:50  후보 생성
  17:10  전략 검증

  18:30  ▶ 블로그 배치 시작
           ① 거래일 가드 (휴장일이면 종료)
           ② 다이제스트 JSON 생성 (약 1분)
           ③ claude -p /blog 로 원고 작성 (약 4분)
           ④ 숫자 대조 검증
           ⑤ 네이버 포맷·문체 검사
         → /opt/maps/blog/2026-09-04.txt

블로그 배치가 18:30인 이유는 18:00 리포트가 끝나야 시장 맥락 발췌가 채워지기 때문입니다.
처음엔 18:00에 같이 돌렸다가 리포트 섹션이 매번 비어서 30분 뒤로 밀었습니다.

원고는 대시보드 화면에서도 볼 수 있게 했습니다.
날짜 고르고 "전체 복사" 누르면 끝입니다. 이것도 5편에서 코드를 붙입니다.


────────────────────
5. 두 달 동안 바뀐 것
────────────────────

시리즈 순서가 곧 제가 겪은 순서입니다.

  7/27  1단계·2단계 구조 완성, 마크다운으로 출력
        같은 날 AI 도구 제한이 안 걸린다는 걸 발견 (3편)
  7/30  마크다운을 버리고 네이버 평문 규약으로 전환 (4편)
  7/31  실제로 붙여넣어 보고 구분선 폭을 33자에서 20자로 (4편)
  8/11  초보자도 읽을 수 있게 원고 구성 개편, 가독성 검사 추가 (4편)
  8/16  원고를 서버 두 곳에 남기도록 변경 (5편)
  8/25  주문 순간의 판단 근거를 다이제스트에 넣음 (2편)
  8/27  데이터 미완성 후보를 순위에서 분리 (2편)

처음부터 이 구조가 나온 게 아닙니다.
매일 나온 원고를 읽다가 "이건 아니다" 싶은 걸 하나씩 고쳤습니다.

다음 편은 1단계, 다이제스트입니다.
DB에서 하루치 JSON을 어떻게 뽑는지, 왜 "미측정"이라는 값이 따로 있는지.
