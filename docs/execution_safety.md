# 계좌 실행 안전 장치 운영 안내

자동후보·분석 픽·분할매매·상한가·시간외 매매의 주문과 취소는 `OrderManager`를 거친다.
이번 변경의 목적은 수익률을 높이는 신호 추가가 아니라, 중복 주문·잘못된 체결 판정·
불완전한 계좌 정보로 인한 주문을 방지하는 것이다.

## 사용자가 보게 되는 변화

| 상황 | 변경 후 동작 |
|---|---|
| 주문 전송 중 연결이 끊김 | 결과 불명으로 보관하고 재전송하지 않는다. 매수·매도 모두 동일하다. |
| 같은 신호가 다시 실행됨 | 계좌와 신호 식별자가 같은 주문을 다시 보내지 않는다. 요청 내용이 달라지면 차단한다. |
| 매수 미체결이 남아 있음 | 기존 보유분과 미체결 예약액까지 더해 투자 한도를 검사한다. |
| 취소 요청이 접수됨 | 실제 취소 내역을 확인하기 전까지 수량·현금 예약을 유지한다. |
| 장부와 증권사 잔고가 다름 | 신규 매수를 차단하고 차이와 근거를 표시한다. 입금이나 출금으로 추측하지 않는다. |
| 손실 한도에 도달함 | 신규 매수를 차단한다. 최신 수량과 소유 관계가 확인되는 기존 포지션의 청산은 가능하다. |
| 오래된 검증만 남아 있음 | 과거 승격 기록이 있어도 실계좌의 일반 전략 신규 매수를 차단한다. |
| 알림 전송이 실패함 | DB에 알림을 남겨 재시도한다. 알림 실패가 주문 상태를 되돌리지 않는다. |

`MAPS_DRY_RUN=true` 또는 `MAPS_LIVE_TRADING_ENABLED=false`이면 매수·매도·취소를 모두
막는다. 조회와 계좌 검증은 가능하다. Kiwoom 실행은 이 계약을 지원할 때까지 차단한다.

## 주문 상태와 재시작

전송 전에 `order_intent`를 커밋하고 `PREPARED → SENDING`으로 기록한다.
브로커의 명확한 응답에 따라 `ACKNOWLEDGED`, `PARTIALLY_FILLED`, `FILLED`,
`CANCELLED`, `REJECTED`로 이동한다. 전송 결과가 불명확하거나 재시작 시 `SENDING`이
남아 있으면 `UNKNOWN`으로 유지한다. 시간 경과, 비슷한 종목·수량의 주문,
잔고에서 종목이 사라졌다는 이유로 체결·거부·취소를 확정하지 않는다.

계좌 식별자는 환경과 계좌번호의 해시다. KIS 주문 식별자에는 환경·계좌·거래일·주문번호를
포함한다. 계좌별 스레드 잠금과 OS 파일 잠금을 함께 사용한다. **단일 호스트 운영이 전제**다.
모든 실행 프로세스는 같은 `MAPS_EXECUTION_LOCK_DIR`를 사용해야 한다. 실행 중 잠금 디렉터리를
바꾸지 않는다. 다중 호스트 배포에는 별도의 DB 기반 소유권 제어가 필요하다.

## 계좌 관측과 손실 한도

첫 관측일은 `WARMUP`이다. 과거 `PortfolioSnapshot`을 새 계좌 기준으로 임의 승계하지 않는다.
다음 날부터 체결 내역·보유 수량·현금·비용을 대조한 완전한 관측을 연결한다.
확인된 입출금과 주식 입출고를 보정한 자산 지수로 일일 손익과 관측 이후 최대 낙폭을 계산한다.
기본 차단 기준은 일일 손실 1.5%, 최대 낙폭 15%다. 과거 계좌 전체 생애의 최대 낙폭을 뜻하지 않는다.

현금 차이 1원을 초과하거나 수량 차이가 있으면 `AccountAdjustment`가 생성되고 신규 매수가
차단된다. 관리자가 증빙을 확인해 입금·출금·수수료·배당·주식 입출고·기타 정정으로 분류한다.
분류만으로 주문이 재전송되거나 즉시 재개되지 않는다. 다음 계좌 검증이 통과해야 한다.
자금 이동 시각은 관측 구간 끝으로 처리하므로 구간 내부의 정밀한 시간가중 수익률은 아니다.

KIS 실계좌는 기간 손익 API의 수수료·세금·이자를 대조한다. 입출금·주식 입출고 자동 조회는
지원하지 않는다. 모의계좌는 비용 조회 API가 없어 관측 비용 기준을 0으로 두고,
차감 비용이 현금 차이로 나타나면 관리자 분류를 요구한다. 조회 실패·페이지 잘림·90일을 넘는
미해결 주문 조회는 완전한 검증으로 간주하지 않는다. 장기 누적 조회도 브로커가 제공한 범위가
불완전하면 차단된다. 인메모리 MockBroker의 재시작으로 잔고가 초기화되어도 차이를 자동 승인하지 않는다.

## 일반 전략의 실매수 자격

일반 전략은 동일한 `validation_run_id`의 Plateau·Monte Carlo·Walk Forward 결과를 사용한다.
실제로 배포할 기본 파라미터를 검증하며, 입력 가격 자료를 압축 저장하고 코드·파라미터·데이터
해시 및 난수 시드도 남긴다. 결과가 누락·불일치하거나 코드/파라미터가 바뀌면 재검증해야 한다.

- 검증 유효기간: 최대 20 KRX 거래일. 휴장일 설정도 반영한다.
- 거래 경험: 완결 거래 20회 이상과 모의 운용 3개월, 또는 63거래일 이상의 동등 리플레이.
- 소액 실전: 거래 가능 점수 75 이상, Plateau C 이상, 표본 외 Sharpe 0.3 이상,
  WFA 통과 및 전략군의 MC 손실 한도 준수.
- 일반 실전: Plateau B 이상, 표본 외 Sharpe 0.5 이상으로 강화한다.

분석 픽과 상한가 자동매매는 저장된 활성화 상태와 종목·소유 관계를 확인하는 별도 정책이다.
일반 전략의 연구 승격 절차만 제외하며, 실행 모드·계좌 검증·예약·노출·손실 한도는 동일하다.

## 관리자 확인 절차

리스크 화면의 ‘계좌 실행 안전 상태’ 또는 `GET /api/v1/risk/execution-safety`에서 차단 사유,
미확정 주문, 미분류 차이, 최근 검증 시각, 버전을 확인한다. 수정 API는 관리자 권한을 요구한다.
인증을 꺼둔 개발 환경에서는 기존 인증 정책에 따라 익명 사용자가 관리자이므로 운영 환경에서는
인증을 활성화한다. 아래 작업은 실제 주문을 제출하지 않는다.

| 작업 | POST 경로 | 추가 필드 |
|---|---|---|
| 불명 주문 해결 | `/api/v1/risk/execution-safety/intents/{id}/resolve` | `outcome`: `link` 또는 `not_accepted`; 연결 시 정확한 `broker_order_id` |
| 기존 주문의 계좌 확인 | `/api/v1/risk/execution-safety/legacy/{id}/resolve` | 위와 동일. 버전은 계좌 상태의 버전 |
| 잔고 차이 분류 | `/api/v1/risk/execution-safety/adjustments/{id}/classify` | `kind`, `amount`, 주식 입출고 시 `quantity_changes` |
| 계좌 차단 해제 | `/api/v1/risk/execution-safety/release-kill` | 새 검증이 완전하며 손실 기준 미만이어야 함 |

공통 요청은 현재 `version`, 8자 이상의 `reason`, 비어 있지 않은 `evidence`를 포함한다.
미접수 확정에는 `evidence.broker_nonacceptance_reference`로 증권사 확인 근거를 남긴다.
단순히 조회되지 않는다는 이유로 미접수 확정하지 않는다. 버전 충돌은 HTTP 409로 반환되며,
최신 상태를 다시 확인해야 한다. 차단 해제는 최고 자산 지수나 손실 기록을 초기화하지 않는다.

```json
{
  "version": 3,
  "reason": "증권사 미접수 확인 자료와 대조 완료",
  "evidence": {"broker_nonacceptance_reference": "확인 자료의 내부 참조번호"},
  "outcome": "not_accepted"
}
```

## 스키마와 검증

Alembic `0038_execution_safety`는 `0037` 다음 리비전이다. 새 테이블 6개와 기존 주문·검증·
승격 기록의 연결 필드를 추가한다. 운영 적용 시 기존 프로세스를 멈추고 DB 백업 후 마이그레이션,
단일 실행 프로세스 시작, 조회 검증, `WARMUP` 및 기존 주문 확인 순서로 진행한다.
기존 데이터를 추측해서 계좌나 검증 실행에 연결하지 않는다. 이번 코드 작업은 운영 DB 변경이나
실거래 활성화를 수행하지 않았다.

비밀 설정 파일을 읽거나 외부 네트워크를 사용하지 않는 전체 검증 명령:

```powershell
.venv/Scripts/python.exe scripts/run_isolated_tests.py tests maps/tests -q --tb=short
```

기본 설정과 신규 설정 항목은 `.env.example`에 있다. 자동 알림은 계좌 동기화 때 재전송하며,
중단 중인 동기화 작업을 대신 실행하는 별도 서비스는 아니다.
