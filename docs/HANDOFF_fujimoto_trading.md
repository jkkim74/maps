## 사용자 의도와 결정

블로그 https://blog.naver.com/mindmethod7/224433147862 를 확인하고 MAPS에 매매법을 구축할 수 있는지 검토했다. 이후 사용자가 다른 세션에서 이어가도록 설계서 저장과 git push를 요청했다.

- 자동매매까지 설계한다.
- 안전형과 원문 기반형을 모두 제공하고 동일 계좌에서 동시 운영한다.
- 전 시장 자동 선별과 장중 호가 판단을 포함한다.
- 기본 전략 예산은 50:50. 원문 비중보다 계좌 공통 한도가 우선한다.
- 안전형은 반전 확인 후 추가 매수, 원문 기반형은 실적 유지 시 하락 추가 매수도 허용한다.
- 지표 기간·RSI 조건·신호일 종가 상한·호가 3배/30초 조건은 검증 전 가설로 사용하기로 했다.

설계서에는 사용자 선택과 설계자가 제안한 세부 연구 기본값을 구분했다. 가설을 실증 완료 값으로 바꾸어 설명하지 않는다. 기능 구현이나 실거래 전환은 이번 저장 작업에 포함되지 않는다.

## 다음 세션 시작 순서

1. `git status --short`로 기존 작업을 확인한다. 이 세션에는 사용자의 미추적 일지 `docs/diary/20260914.txt`, `docs/diary/20260916.txt`가 있었고 수정·커밋하지 않았다.
2. 설계서 전체를 읽고 확정 범위를 유지한다. 자동매매 구현 요청이 주어졌을 때 아래 작업을 시작한다.
3. `.agent/PLANS.md` 존재를 재확인한다. 이번 조사에서는 없었다. 계속 없다면 목적·진행·결정·검증·복구 절차의 계획 규약과 본 작업 ExecPlan을 먼저 작성한다.
4. 첫 구현 단위는 **데이터 계약·규칙 평가·시점 누출 회귀 테스트**로 잡는다. 주문 연결은 하지 않는다.
5. 설계서의 세부 수식·체결 경계 규칙을 실행 가능한 구현 계획으로 고정하고, 이후 원장·리플레이 → 주문·구독 → 화면·운영 순서로 진행한다.

### 구현 계획에서 반드시 구체화할 항목

아래는 범위 재선택이 아니라 코드와 데이터에 맞춰 고정해야 할 구현 세부다. 결정과 근거를 ExecPlan에 남긴다.

- RSI 평활·초기화와 무손실/상수 가격 처리, 완성 주봉 캘린더, 일목 시프트 경계.
- 3개년 확정 실적·배당의 공급원과 자료 가용 기간, 비교 가능한 연결/별도 기준, 분할 등 기업행사 처리.
- 매수 레그의 부분 체결·취소 후 완료 판정, 미체결 신호의 유효기간과 재평가, 정수 수량과 마지막 매도 잔량.
- 분할 청산의 일회성 반등 축소와 일반 매도 단계가 동시에 발생할 때의 우선순위.
- 모드별 자산 평가·입출금·예산 변경 시점 및 동일 종목 신호 경합 처리.
- 실적 훼손·가격 손절의 주문 유형, 거래정지·하한가·시세 단절 때의 처리. 피드 장애를 청산 완료로 간주하지 말 것.
- KIS 공식 구독 한도와 현재 상한가 엔진 점유량. 전 종목 실시간 구독을 가정하지 말 것.
- 호가 저장 용량·보존 기간·재생 체결 모델, 독립 검증 표본의 최소 기준.
- 전략 ID·원장 타입·API·마이그레이션 명칭. 기존 코드와 중복되지 않도록 정할 것.

## 검증과 출시

- 개발: `MAPS_BROKER_MODE=mock`, 실거래 비활성화. 격리 DB와 외부 서비스 대역 사용.
- 관련 테스트 후 `python -m pytest --tb=short`, 시장·점수 변경 시 `python -m pytest maps/tests -q`도 실행한다.
- 문서 지도는 `python -m pytest tests/test_docs_index.py -q`로 검사한다.
- 마이그레이션·카탈로그 등록·두 모드 소유 수량·UNKNOWN 주문 재시도 방지·상한가 피드 회귀를 포함한다.
- 성과 검증은 모드별·합산·호가 기능 유무를 분리한다. 과거 근거가 없는 구간은 검증 부족으로 남긴다.
- 관찰 → 모의 검증 → 기존 승격 게이트와 합산 위험 검증 통과 순으로 진행한다. 저장 요청을 운영 활성화 승인으로 해석하지 않는다.
- 기존 보유분은 자동 편입·청산하지 않는다. 신규 전략의 자동매도 규칙 승인을 활성화 시 기록하며 비상 일괄 청산은 별도 승인이다.
