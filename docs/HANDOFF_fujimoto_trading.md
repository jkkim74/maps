### 운영 배포 결과

2026-10-08 운영 `/opt/maps`에 릴리스 `9c7f526`을 적용했고 DB는
`0041_fujimoto_trading`이다. 내부·외부 `/health` 정상, `/fujimoto` 비로그인 303,
상태 API 비인증 401을 확인했다. 런타임 활성화는 false이고 후지모토 설정·사이클·주문은
각 0건이다. 기존 보유분의 편입이나 전략 활성화는 하지 않았다.

배포 전 PostgreSQL 백업은 서버의
`backups/maps_fujimoto_20261008_003319_9c7f526c.dump`이며 목록 검증을 통과했다.
첫 시도는 30초 상태 검사 제한이 기존 기동 시간보다 짧아 이전 코드로 복구했다.
기존 로그에서 약 70초~4분 이상의 기동 시간을 확인한 후 대기 시간을 늘려 재배포했고
09:41 KST 애플리케이션 초기화와 정상 응답을 확인했다. 재시도 전 백업은
`backups/maps_fujimoto_20261008_003818_9c7f526c.dump`다. DB 다운그레이드는 하지 않았다.

운영의 기존 KIS 모의 WebSocket(`ops.koreainvestment.com:31000`)은 초기 HTTP 응답이
종료되는 연결 오류로 재시도 중이다. 복구했던 이전 커밋에서도 같은 오류를 확인했다.
따라서 웹 배포 성공과 실시간 피드 정상화를 구분해야 한다. 이 연결 문제의 원인은
확정하지 않았으며, 실시간 거래 준비가 완료됐다고 판단하지 않는다.

- 안전형 `fujimoto_safe_v1`과 원문형 `fujimoto_original_v1`이 시점 근거,
  완성 봉 지표, 분할 매매 판단과 체결 상태 전이를 공유한다.
- 별도 소유 원장·예약·실제 비용을 기록하고 기존 OrderManager와 계좌 위험 검사를
  사용한다. 같은 종목의 두 모드와 기존 전략 보유분을 구분한다.
- 전용 리플레이는 다음 세션 지정가, 거래량 제한, 비용, 부분 체결을 재현한다.
  모드별·합산·호가 사용 여부에 따른 검증 결과와 입력 지문을 저장한다.
- 운영 연결은 실제 수집·장 마감 선별, 기존 KIS 연결을 공유하는 호가 기록,
  계좌 대조와 주문 복구, 관리자 화면 `/fujimoto`와 소유자 범위 API를 포함한다.
- 마이그레이션은 `0041_fujimoto_trading`이다. 새 기능의 기본값은 비활성/관찰이며,
  계좌 전용 예산은 자동 배정하지 않는다. 배포는 실거래 활성화 승인이 아니다.

### 운영 전 확인할 제약

소프트웨어 테스트와 전략의 수익성 검증은 별개다. 과거 시점의 재무·배당·업종·PER,
기업행사 후 주당 지표 비교 가능성, 실제 호가 테이프 및 독립 거래 표본이 부족하면
검증 부족으로 남기며 신규 진입을 허용하지 않는다. 현재 자료를 과거에 소급하지 않는다.

확정 체결 수량과 수수료·세금 정산 완료는 구분한다. 비용 미확정은 신규/추가 매수와
비용 차감 후 호가 이익 매도를 차단하지만, 소유 수량이 확인된 승인된 손절·실적·기술적
청산을 막는 이유로 쓰지 않는다. 결과 불명 주문과 취소 요청의 예약은 확정 전 유지한다.

검증 리플레이는 활성화 단계에서 수행하고, 진입에서는 코드·입력·설정·호가 변형·계좌
한도·승격의 동일성과 유효기간을 확인한다. 재검증 계산이 계좌 실행 잠금을 오래 점유하지
않도록 했다. 호가와 압축 후보 근거에는 저장 한도가 있으며, 소진 시 결측을 표시하고
호가 조건을 중단한다. 검증에 사용한 불변 근거를 자동 삭제하지 않는다.

초기 기록 한도는 후보 10,000건과 계좌별 호가 100,000건인 관찰용 기본값이다.
장기 검증 전에 실제 종목 수·재선별 횟수·호가 빈도·디스크와 메모리를 산정해 한도를
설정한다. 지원 상한은 후보 2,000,000건, 계좌별 호가 100,000,000건이며, 이 숫자는
저장·분석 처리 성능 보장이 아니다. 한도를 늘려도 과거의 기록 공백은 복구되지 않는다.

호가 기능을 끈 연구도 안전형 손절을 평가할 보유 구간의 실제 기록이 필요하다.
3초를 넘는 설명되지 않은 공백이나 일봉 저가만으로 추정한 장중 체결 순서는 검증
부족으로 남긴다. 기록된 제한·거래정지·연결 장애는 실제 실행 불가로 측정한다.
후보 슬롯은 운영과 리플레이 모두 기록된 순위를 따르므로 상위 후보의 신선한 호가가
없을 때 일부 자금이 대기할 수 있다.

부분 체결은 동일 주문의 누적 수량·비용·잔량으로 유지한다. 호가만으로는 취소 확인을
증명할 수 없으므로, 리플레이의 제출 후 미완료 주문은 세션 종료 시 UNKNOWN으로 남고
검증을 차단한다. 실제 운영에서는 기존 브로커 대조가 종료 확정의 근거다.

기존 보유분은 자동 편입하거나 청산하지 않는다. 신규 전략 소유분의 매도 규칙 동의,
모의 단계와 기존 실거래 승격 조건, 두 모드 합산 검증을 별도로 충족해야 한다.

아래 내용은 최초 설계 세션의 조사 기록이다. 현재 진행 상태는 위 실행 계획이 정본이다.

설계서에는 사용자 선택과 설계자가 제안한 세부 연구 기본값을 구분했다. 가설을 실증 완료 값으로 바꾸어 설명하지 않는다. 최초 설계 저장 작업에는 기능 구현이나 실거래 전환이 포함되지 않았다.

## 최초 구현 착수 순서 (이력)

1. `git status --short`로 기존 작업을 확인한다. 이 세션에는 사용자의 미추적 일지 `docs/diary/20260914.txt`, `docs/diary/20260916.txt`가 있었고 수정·커밋하지 않았다.
2. 설계서 전체를 읽고 확정 범위를 유지한다. 자동매매 구현 요청이 주어졌을 때 아래 작업을 시작한다.
3. `.agent/PLANS.md` 존재를 재확인한다. 이번 조사에서는 없었다. 계속 없다면 목적·진행·결정·검증·복구 절차의 계획 규약과 본 작업 ExecPlan을 먼저 작성한다.
4. 첫 구현 단위는 **데이터 계약·규칙 평가·시점 누출 회귀 테스트**로 잡는다. 주문 연결은 하지 않는다.
5. 설계서의 세부 수식·체결 경계 규칙을 실행 가능한 구현 계획으로 고정하고, 이후 원장·리플레이 → 주문·구독 → 화면·운영 순서로 진행한다.

### 구현 계획에서 반드시 구체화할 항목

아래는 범위 재선택이 아니라 코드와 데이터에 맞춰 고정해야 할 구현 세부다. 결정과 근거를 ExecPlan에 남긴다.

- RSI 평활·초기화와 무손실/상수 가격 처리, 완성 주봉 캘린더, 일목 시프트 경계.
- 3개년 확정 실적·배당의 공급원과 자료 가용 기간, 비교 가능한 연결/별도 기준, 분할 등 기업행사 처리.
- 매수 레그의 부분 체결·취소 후 완료 판정, 미체결 신호의 유효기간과 재평가, 정수 수량과 마지막 매도 잔량.
- 분할 청산의 일회성 반등 축소와 일반 매도 단계가 동시에 발생할 때의 우선순위.
- 모드별 자산 평가·입출금·예산 변경 시점 및 동일 종목 신호 경합 처리.
- 실적 훼손·가격 손절의 주문 유형, 거래정지·하한가·시세 단절 때의 처리. 피드 장애를 청산 완료로 간주하지 말 것.
- KIS 공식 구독 한도와 현재 상한가 엔진 점유량. 전 종목 실시간 구독을 가정하지 말 것.
- 호가 저장 용량·보존 기간·재생 체결 모델, 독립 검증 표본의 최소 기준.
- 전략 ID·원장 타입·API·마이그레이션 명칭. 기존 코드와 중복되지 않도록 정할 것.

## 검증과 출시

- 개발: `MAPS_BROKER_MODE=mock`, 실거래 비활성화. 격리 DB와 외부 서비스 대역 사용.
- 관련 테스트 후 `python -m pytest --tb=short`, 시장·점수 변경 시 `python -m pytest maps/tests -q`도 실행한다.
- 문서 지도는 `python -m pytest tests/test_docs_index.py -q`로 검사한다.
- 마이그레이션·카탈로그 등록·두 모드 소유 수량·UNKNOWN 주문 재시도 방지·상한가 피드 회귀를 포함한다.
- 성과 검증은 모드별·합산·호가 기능 유무를 분리한다. 과거 근거가 없는 구간은 검증 부족으로 남긴다.
- 관찰 → 모의 검증 → 기존 승격 게이트와 합산 위험 검증 통과 순으로 진행한다. 저장 요청을 운영 활성화 승인으로 해석하지 않는다.
- 기존 보유분은 자동 편입·청산하지 않는다. 신규 전략의 자동매도 규칙 승인을 활성화 시 기록하며 비상 일괄 청산은 별도 승인이다.
