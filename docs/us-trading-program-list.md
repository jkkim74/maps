## 1. 목적과 범위

관리자 수동 주문과 자동 체결 추적·대사·복구를 구현하고, 향후 전략을 공통 실행 경로에 연결한다.

| 구분 | 범위 |
|---|---|
| 이번 구현 | 계좌 연결, 조회, 지정가 주문·취소, 체결 대사, 보유 귀속, 관리자 화면 |
| 확장 기반 | 공통 주문 계약, 실행 출처 검증, 전략 식별·버전 기록, 인스턴스별 수량·예약 |
| 후속 구현 | 실제 전략, 전략 실행기, 백테스트·승격 정책, 전략 활성화 화면 |
| 제외 | 실거래, 자동 환전, 소수점·시간외·신용 거래, 모바일 앱 확장 |

첫 버전은 미국 정규장·USD·정수 수량·지정가·허용 종목만 지원한다. 미국 계좌의 인증정보·토큰·잔고·주문·손실 한도는 국내 계좌와 분리한다. 기본 환경은 로컬 `mock`, KIS 연동은 모의환경만 허용하고 주문 활성화는 기본 해제한다.

## 3. 공통 주문 계약과 전략 확장

관리자 화면과 향후 전략 실행기는 같은 실행 서비스를 사용한다. 브로커 어댑터는 주문을 만든 전략의 종류를 알 필요가 없다.

`관리자 요청 또는 전략 판단 → 공통 주문 요청 → 실행 자격·리스크 검사 → 주문 기록·제출 → 체결 대사`

| 정보 | 주요 항목 | 처리 원칙 |
|---|---|---|
| 실행 대상 | 계좌, 환경, 시장, 통화 | 서버가 결정하며 브라우저가 임의 변경하지 못함 |
| 주문 내용 | 종목, 거래소, 방향, 수량, 지정가 | 정규장·정수 수량·지정가로 제한 |
| 중복 방지 | 요청 ID, 판단 이벤트 ID | 동일 요청은 기존 처리 결과 반환 |
| 주문 출처 | 수동/전략, 실행 인스턴스 | 인증된 서버 경로에서 부여 |
| 전략 근거 | 전략 ID·버전, 파라미터 스냅샷 | 수동 요청에는 전략 정보를 허위 생성하지 않음 |
| 판단 유효성 | 판단 시각, 유효기간, 데이터 근거 | 만료·미래 데이터·불완전 근거 차단 |
| 보유 귀속 | 진입 인스턴스, 매도 대상 | 다른 인스턴스 보유분의 매도 금지 |

첫 버전의 수동 거래는 서버가 관리하는 수동 실행 인스턴스에 귀속한다. 전략 출처의 운영 활성화는 제공하지 않는다.

- 전략은 주어진 데이터와 보유 상태로 판단을 만들며, 브로커 호출·주문 재시도·체결 확정은 실행 계층이 담당한다.
- 향후 봉 기반 전략은 기존 `BaseStrategy.generate_signals()`를 재사용하고 실행기가 신호를 공통 주문 요청으로 변환한다.
- 상태형·분할매매 전략도 같은 주문 계약에 연결하되 범용 상태형 전략 엔진은 이번에 구현하지 않는다.
- 개별 전략명을 `OrderManager` 조건문에 추가하지 않는다. 등록과 활성화를 구분하고 전략별 실행 자격을 검증한다.
- 시장 규칙은 전략 밖에서 처리한다. 미국 가격에 KRX 가격 정렬을 적용하지 않는다.
- 새 주문 유형이나 데이터 종류가 필요한 전략은 별도 기능 확장이 필요하다.

## 4. 실행·회계 안전 원칙

- 계좌 잠금과 영속 예약을 공유해 여러 실행 인스턴스가 동일 현금을 중복 사용하지 못하게 한다.
- 보유 귀속은 계좌·실행 인스턴스·종목 기준으로 관리하고 브로커 보유 총량과 별도로 대사한다.
- 금액은 Decimal/Numeric, 이벤트 시각은 UTC, 미국 세션은 `America/New_York` 기준으로 처리한다.
- 전체 페이지를 읽고 정확한 주문 식별자로 대사한다. API 미지원·조회 불완전은 성공이나 빈 결과로 취급하지 않는다.
- 응답 불명 주문은 `UNKNOWN`과 예약을 유지하고 자동 재전송하지 않는다. 취소 접수와 취소 완료를 구분한다.
- 기동 시 대사를 먼저 수행한다. 기본 60초 주기로 동기화하고 미확정 주문은 장외에도 추적한다.
- 시세·달력·대사 정보가 부족하면 신규 주문을 차단한다. 기존 보유분은 자동 편입하지 않는다.
- 매도는 명시적 승인과 귀속 수량을 검증한다. 신규 매수 중단이 보유분 청산이나 기존 주문 취소를 의미하지 않는다.
- 확인되지 않은 수수료·배당·분할·입출금은 미확정으로 보존한다.

## 5. 관리자 API 목록

기본 경로: `/api/v1/us-trading`

| 메서드·경로 | 기능 | 주요 반환·처리 |
|---|---|---|
| `GET /status` | 연결·실행·시장 상태 | 환경, 마스킹 계좌, 세션, 신규 진입 차단 사유 |
| `GET /account` | USD 계좌 조회 | 현금, 주문 가능 금액, 평가액, 조회 시각 |
| `GET /positions` | 보유 조회 | 브로커 수량, 귀속 수량, 예약 수량, 매도 가능 수량 |
| `GET /quotes` | 허용 종목 시세 | 가격, 관측 시각, 지연·품질 상태 |
| `GET /orders` | 주문 목록 | 상태·기간 필터, 페이지 조회 |
| `GET /orders/{id}` | 주문 상세 | 주문·체결·취소·감사 이력 |
| `POST /orders/preview` | 제출 전 검사 | 주문 금액, 한도 검사, 차단 사유. 주문 제출·자금 예약 없음 |
| `POST /orders` | 주문 제출 | 최신 조건 재검사 후 영속 예약·단일 제출 |
| `POST /orders/{id}/cancel` | 취소 요청 | 취소 접수와 확정 상태 구분 |
| `POST /sync` | 동기화 요청 | 중복 실행 방지, 작업 상태 반환 |
| `POST /entry-stop` | 신규 진입 중단 | 기존 주문·보유 유지, 중단 행위 감사 |
| `POST /entry-resume` | 수동 중단 해제 | 수동 중단만 해제. 다른 위험 차단은 유지 |
| `GET /events` | 운영 이력 조회 | 대사 오류, 차단 사유, 관리자 조작 |

모든 경로에 관리자 권한을 적용한다. 화면에서 버튼을 숨기는 것과 별개로 서버에서도 권한과 실행 조건을 검사한다. API 스키마는 기존 `maps/api/schemas.py` 규칙을 따른다.

## 7. 구현 순서와 완료 조건

1. 계좌·공통 계약 및 스키마
2. 어댑터·시장 규칙·대사
3. 공통 실행·리스크·보유 귀속
4. 관리자 API·화면·운영 기록
5. 전략 확장 계약 테스트·국내 회귀·KIS 모의 검증

구현 시 `.agent/PLANS.md`에 따라 ExecPlan과 관련 패키지 문서를 갱신한다. 허용 종목과 주문·노출·손실 한도를 명시적으로 설정한 뒤 활성화한다.

완료 조건은 수동 모의매매가 안전하게 동작하고, 테스트용 전략을 연결할 때 주문·브로커·대사 코드를 고칠 필요가 없는 것이다. 실제 전략의 성능 검증과 운영 활성화는 별도 작업이다.

## 8. 구현 추적

구현 및 검증 현황은 [ExecPlan](superpowers/plans/2026-10-16-us-paper-trading.md), 설정과 제한은 [운영 안내](US_TRADING_RUNBOOK.md)에 기록한다. 실제 KIS 모의계좌 연동 완료를 의미하지 않는다.

|---|---|
