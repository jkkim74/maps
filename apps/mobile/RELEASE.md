# MAPS Mobile — Signed Release APK

How to build a **signed release APK** for internal / store distribution.

The debug APK flow (`assembleDebug`) is unchanged and needs no keystore. This doc
covers the **release-signed** build only.

> **Why scripts instead of committed gradle files?**
> `apps/mobile/android/` is gitignored — it is generated by `npx cap add android` and
> rewritten by `npx cap sync`. We cannot commit the signing config directly, so it is
> delivered as committed templates + scripts that **re-apply** the config after each
> sync. Secrets live only in `apps/mobile/keystore.properties` (gitignored).

## 1. One-time: generate a keystore

Use the JDK 21 `keytool` (same JDK used to build). From `apps/mobile/`:

```powershell
& "C:\Program Files\Eclipse Adoptium\jdk-21.0.11.10-hotspot\bin\keytool.exe" `
  -genkeypair -v `
  -keystore maps-release.jks `
  -alias maps `
  -keyalg RSA -keysize 2048 -validity 10000
```

`keytool` prompts for a store password, a key password, and a distinguished name.
**Keep the keystore file and both passwords safe** — losing them means you can never
ship an update to the same app listing. The generated `maps-release.jks` is gitignored.

## 2. One-time: create keystore.properties

Copy the template and fill in the real values:

```powershell
Copy-Item keystore.properties.example keystore.properties
```

`apps/mobile/keystore.properties`:

```properties
storeFile=maps-release.jks        # absolute path, or relative to apps/mobile/
storePassword=<store password>
keyAlias=maps
keyPassword=<key password>
```

`keystore.properties` and `*.jks` / `*.keystore` are gitignored — never commit them.

## 3. Build the signed APK (one command)

From `apps/mobile/`:

```powershell
npm run build:apk:release
```

This chains:

1. `npm run build` — TypeScript + Vite web build
2. `cap sync android` — copy web build into the native project
3. `node scripts/apply-release-signing.mjs` — inject the release `signingConfigs`
   block into `android/app/build.gradle` (idempotent; reads `keystore.properties`
   at gradle build time — no passwords are written into build.gradle)
4. `node scripts/gradle-release.mjs` — run `gradlew assembleRelease` with JDK 21

**Prerequisite:** the Android project must already exist. If this is a fresh checkout:

```powershell
npm run cap:add:android   # once, generates android/
```

**JDK 21:** `scripts/gradle-release.mjs` defaults `JAVA_HOME` to
`C:\Program Files\Eclipse Adoptium\jdk-21.0.11.10-hotspot`. On another machine, set
`MAPS_JAVA_HOME` (or `JAVA_HOME`) to your JDK 21 install before running.

## 4. Output

The signed APK lands at:

```
apps/mobile/android/app/build/outputs/apk/release/app-release.apk
```

Distribute this file directly (internal install) or upload to your store channel.

## Notes

- **Re-running after `cap sync`:** `cap sync` overwrites `build.gradle`. The
  `build:apk:release` script always re-applies signing, so just re-run it. To only
  re-apply signing without a full build: `npm run signing:apply`.
- **If `keystore.properties` is missing:** the gradle block prints a warning and the
  release APK is produced **unsigned** (it will not install without a signature).
- **appId / applicationId:** `kr.maps.mobile` (see `capacitor.config.ts`).
